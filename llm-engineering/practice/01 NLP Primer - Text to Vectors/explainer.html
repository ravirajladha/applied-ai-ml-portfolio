Corpus, token, tokenization

Cutting text into pieces the model can count.

Corpus

The pile of text a model learns from — like a student's entire library. A model rarely knows what its library lacked.

Token

One piece of text the model reads: a word, a part of a word, a dot, even one byte. Think Lego brick.

Tokenization

Cutting text into tokens and giving each an integer ID. Think of sorting text into Lego bricks.

Type anything. The toy tokenizer below uses a small list of sub-word pieces and always grabs the longest piece that fits.

Why you should care. Context length, API price and speed are all counted in tokens, not words. Llama 3 was trained on about 15 trillion tokens. The same sentence can cost a lot more tokens in Hindi or code than in plain English.
3

Vocabulary and OOV

A fixed menu of pieces, and what happens when you order something not on it.

Vocabulary (|V|) — the complete, fixed list of tokens a model knows, each with an ID. Like a restaurant menu: decided once, cannot change without reprinting. Llama 3: 128,256 items. Gemma 3: 262,144.

OOV (out-of-vocabulary) — a word that is not on the menu. Old word-level models wrote [UNK] (“unknown”) and lost the meaning completely.

Try a made-up word. Watch the three strategies handle it. Our mini word-menu: the, cat, sat, on, mat, dog.

Trade-off. A bigger |V| → fewer tokens per sentence, but a larger embedding table (more parameters). Modern LLMs use byte-level BPE (Byte-Pair Encoding: learn frequent pieces from the corpus; fall back to raw bytes), so nothing is ever unknown — just sometimes expensive.

One-hot vs embedding

Two ways to turn a token ID into a list of numbers.

One-hot — a row of switches, all OFF except one. Like a hotel key-card that only opens room 7: it names the word and says nothing else. Embedding — a short list of learned numbers (size d) per word, like GPS coordinates: nearby places are similar places.

Click a word. Left: its one-hot (length = |V|). Right: its position on a made-up 2-number embedding map.

One-hot

toy embedding map (d = 2). Real models use d = 4096 or more.
The trick. Multiplying a one-hot vector by the embedding table E just picks one row — so real models skip the multiplication and index directly. The table has |V| × d numbers: Llama 3 8B has 128,256 × 4,096 ≈ 525 million parameters just there. They start random and training nudges them until similar words sit close together.
5

Static vs contextual embeddings

Does a word get the same vector everywhere?

Static (word2vec, GloVe): one fixed vector per word — like a dictionary with one entry per word. Contextual: the vector is recomputed from the surrounding words — like a human reading the sentence. Each Transformer layer mixes in the other tokens using attention (each token looks at the others and borrows what's relevant).

Pick a sentence. The word “bank” is the same on the page, but where does it land on the map?

Static = starting point (an LLM's input table is static). Contextual = what the hidden layers produce. That's why LLMs “understand” context.

Cosine similarity

Closeness in meaning becomes geometry.

Analogy. Two people pointing at things. If they point the same way they agree (1). At right angles they're unrelated (0). Opposite = disagree (−1). Only the direction matters, not how long the arm is.

Drag the angle between the two arrows.

cos θ = (a · b) / (|a| |b|) — dot product (multiply slot by slot, add up) divided by both lengths.

Semantic similarity = how close in meaning, even with no shared words: “How do I reset my password?” ≈ “I forgot my login details”. Embed both, take the cosine. This is the engine of RAG (Retrieval-Augmented Generation: fetch the documents most similar to a question, hand them to the LLM).
7

Language model & autoregression

The one idea behind every LLM: guess the next token.

Language model — a model giving a probability for each possible next token. Like your phone keyboard's suggestion strip. Autoregressive — produce one token, add it to the input, then predict the next one. Left to right, one at a time.

A tiny model learned from six sentences about a cat and a dog. Click a suggested next word to build a sentence.

Why it matters. This is why answers stream word by word, and why long answers are slow: one full model pass per generated token. Always picking the top word (“greedy”) repeats itself; real chatbots sample in proportion to the probabilities.
8

Three ways to build a Transformer

Transformer = the network design (attention-based) that all of these use.

Encoder-only

Reader. Sees the whole text, both directions. Produces understanding, not new text.

BERT, RoBERTa — classification, NER, the embedding models inside RAG.

Decoder-only

Writer. Reads left to right, each token sees only earlier ones, predicts the next.

GPT, Llama 3, Qwen3, DeepSeek-V3 — almost every modern LLM. This course.

Encoder-decoder

Translator. Encoder reads all the input; decoder writes the output while looking back at it.

Original Transformer, T5, BART — translation, summarization.

What it is all used for

NLU (Natural Language Understanding) pulls meaning out. NLG (Natural Language Generation) makes new text. LLMs are generators, but handle NLU by generating the answer, e.g. the word “positive”.

TaskOne lineExample
Text classificationOne label for the whole textspam / not spam; positive / negative
NER (named entity recognition)Find names of real things and tag their type[Charles Darwin]PERSON published in [London]PLACE in [1859]DATE
POS tagging (part of speech)Grammar role of each word; same word can change role“book a flight” → VERB · “read a book” → NOUN
Machine translationSame meaning, another languageWhere is the station? → स्टेशन कहाँ है?
SummarizationShorter text, same key points10-page report → 5 bullets
