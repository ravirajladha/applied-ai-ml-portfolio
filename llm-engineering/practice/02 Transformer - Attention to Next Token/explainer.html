1

The assembly line

An LLM is a factory with four stations. Click each one.

🌍 Analogy — a meeting. Each token is a person at a table holding a note card (its vector). In every round (a block), people first listen to each other (attention) and update their card, then each thinks quietly alone (feed-forward) and updates it again. After N rounds, the last person's card is read out to vote on the next word.
2

Why attention?

The embedding table gives "it" the same vector in every sentence. But what "it" means depends on the other words.

Click a word to see which earlier words it would mostly "listen to" (hand-set weights, to show the idea).

Same word it, different sentence → it listens to a different word (animal vs street) → it ends up with a different vector. That new vector is the contextual embedding from topic 01. Attention is the machine that makes embeddings contextual.
3

Query, Key, Value — the library search

Each token's vector is turned into three smaller vectors by three learned weight matrices.

NamePlain meaningLibrary analogyIn code
Query (Q)"What am I looking for?"What you type in the search boxQ = X @ Wq · q_proj
Key (K)"What do I contain?" (a label)The title on each book's spineK = X @ Wk · k_proj
Value (V)"What I hand over if picked"The book's actual contentV = X @ Wv · v_proj

Four steps, always the same:

  1. Score: how well does my Query match each Key? → dot product Q·K (big = good match).
  2. Scale: divide by √d (d = length of K) so scores don't get huge.
  3. Softmax: turn scores into percentages that add to 100%. These are the attention weights.
  4. Blend: new vector = weighted mix of the Values.

Attention(Q,K,V) = softmax( Q·Kᵀ / √d ) · V

Live demo — token "it" (the query) looks at 3 tokens. Drag the sliders to change how well each Key matches the query; watch the weights and the blended output change.

The one thing to remember: the scores decide who you listen to; the Values are what you hear. Every attention layer in every LLM is this, done for all tokens at once with matrices.
4

No peeking: the causal mask

A decoder (GPT, Llama, Qwen) is trained to predict the next word. If token 2 could see token 3, that's cheating.

Rows = the token doing the looking. Columns = the token being looked at. Grey = blocked.

How it's done in code: before softmax, put −∞ in every blocked cell. e−∞ = 0, so softmax gives those cells exactly 0% weight. That's the whole trick — one line, np.triu, in the notebook.
This is why the first token can only attend to itself (its row is 100% on itself) — and why, during training, all positions can be computed in parallel without cheating (Session 2: "teacher forcing").
5

Many heads = many reading glasses

One attention computation can only focus one way. So the model runs several in parallel, each smaller.

Each head has its own small Wq, Wk, Wv. Their outputs are glued side by side (concat) and mixed by one more matrix, Wo (o_proj in code). Example: GPT-2 small has d = 768 split into 12 heads of 64.
We didn't hand-design "pronoun head" etc. — heads learn their own roles; the labels here are illustrations.
6

One block, stacked N times

A Transformer block = attention + feed-forward, each wrapped with a "norm" and a "residual add".

x ─┬─► Norm ─► Multi-head Attention ─►(+)─┬─► Norm ─► Feed-Forward (MLP) ─►(+)─► to next block
   └──────────────── residual ────────────┘   └──────────── residual ─────────┘

Attentiontalk between tokensthe meeting discussion

Click to push the token "it" through blocks. Watch its vector change a little each time (it is only ever added to).

Real sizes: GPT-2 small = 12 blocks · Llama 3 8B = 32 · Qwen2.5-0.5B (your assignment model) = 24. Parameters per block ≈ 12·d² (attention 4d² + FFN 8d²) — the formula from Session 2.
7

LM head & generation

After the last block, only the last token's vector is used to choose the next token.

  1. Multiply the last vector by the unembedding matrix (often the embedding table flipped, Eᵀ) → one score (logit) per vocabulary token.
  2. Softmax → probabilities.
  3. Pick one (highest = greedy, or sample) → append → run the whole thing again.

Toy generator with made-up probabilities. Each click = one full pass through the model.

This loop is why long answers are slow (one pass per token) and why the context window includes the output — every generated token is appended and re-read.

Finding it in real code

This is print(model) for Qwen/Qwen2.5-0.5B — the model in your Assignment 1A notebook (trimmed). Every line is something from this page.

Qwen2ForCausalLM(
  (model): Qwen2Model(
    (embed_tokens): Embedding(151936, 896)          ← §1 embedding table E  (|V| × d)
    (layers): ModuleList(
      (0-23): 24 x Qwen2DecoderLayer(               ← §6 the block, stacked 24 times
        (self_attn): Qwen2Attention(                ← §3 attention
          (q_proj): Linear(896 → 896)               ←   Wq   (14 heads × 64)
          (k_proj): Linear(896 → 128)               ←   Wk   (2 shared KV heads × 64)
          (v_proj): Linear(896 → 128)               ←   Wv
          (o_proj): Linear(896 → 896)               ← §5 Wo, mixes the heads
        )
        (mlp): Qwen2MLP(                            ← §6 feed-forward "think"
          (gate_proj), (up_proj): Linear(896 → 4864)
          (down_proj): Linear(4864 → 896)
        )
        (input_layernorm), (post_attention_layernorm): Qwen2RMSNorm(896)   ← §6 norms
      )
    )
    (norm): Qwen2RMSNorm(896)
    (rotary_emb): Qwen2RotaryEmbedding()            ← position (RoPE, Session 1 §11)
  )
  (lm_head): Linear(896 → 151936)                   ← §7 LM head
)
Now your assignment line makes sense:
LoraConfig(r=16, target_modules=['q_proj','v_proj'])
= "attach small LoRA matrices B·A next to Wq and Wv inside the attention of all 24 blocks; freeze everything else". You're choosing which matrices from §3 get fine-tuned.
Why is k_proj smaller (128) than q_proj (896)? Grouped-query attention: 14 query heads share 2 key/value heads to save memory at inference. A Module 3/4 topic — just recognise the name for now.
