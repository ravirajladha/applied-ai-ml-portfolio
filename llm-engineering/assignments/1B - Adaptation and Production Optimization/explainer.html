Why a baseline first? Every later claim ("the adapter is better", "4-bit is cheaper") is a comparison. Without a saved "before", you have nothing to compare against.

The prompt template Question: {q}\nAnswer: is fixed in CONFIG. A base model has no chat training, so this plain framing is the fairest no-system-prompt format. Changing the wording between runs would change the results, which is why it lives in one place.

bf16 vs fp16: two 16-bit number formats. bf16 has a wider range; fp16 has finer precision. A T4 only does fp16 fast, and for inference fp16 is safe. The notebook picks automatically.

Distinct-2 (computed in the notebook): unique word pairs ÷ all word pairs. Low = repetitive. A quick, objective diversity number to cite in your 100-word analysis. Seed: makes "random" sampling repeatable across runs.

7Speculative decoding · Part C2 · 2 marks

Analogy. A junior (the 0.5B draft) types the next few words of a reply quickly. The senior (the 1.5B target) reads all of them at once and accepts the ones they would have written, up to the first mistake, which they fix. The reply is exactly the senior's, but the senior spends time reading instead of typing.

Formula (Leviathan et al., 2023): tokens per round = (1 − αk+1) / (1 − α); speed-up ≈ that ÷ (1 + k·c).

Why your measured gain may be small: parameters suggest the 0.5B draft costs ⅓ of the 1.5B. But at batch size 1, each step's time is mostly fixed overhead (launching GPU kernels for every layer: 24 vs 28 layers), so the real c is closer to 0.6–0.8. Set c = 0.7 above and watch the speed-up shrink. That is a strong, evidence-based inference to write.

Lossless: with greedy decoding the output is the same as the target alone; the notebook checks this. Draft model: the small, fast model that guesses. Target model: the big model whose output you actually want.

84-bit quantization and honest benchmarking · Part C3

What 4-bit buys and what it costs

16-bit weights (1.5B)≈ 3.1 GB
4-bit NF4 (embeddings stay 16-bit)≈ 1.2 GB
Analogy. Vacuum-packing your clothes. The suitcase gets much lighter (VRAM ↓), but every time you want a shirt you must unpack it first (dequantization). If you grab shirts one at a time (batch size 1), all that unpacking can make you slower.

So expect: VRAM goes down a lot; throughput may go down on a T4; cost per token can go up. 4-bit pays off when memory is the bottleneck: a bigger model on a cheap GPU, many models or adapters on one GPU, or large batches.

Throughput: tokens produced per second. Latency: time for one request. Peak VRAM: the most GPU memory used at any moment. Dequantization: expanding 4-bit weights back to 16-bit just before each multiplication.

9Cost per 1M tokens · Part C3 · 3 marks
