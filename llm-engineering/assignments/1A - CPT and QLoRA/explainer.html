1The big picture

Analogy. Qwen2.5-0.5B is a bright graduate who has read most of the internet. You want a Linux helpdesk specialist.
① CPT: hand them a stack of Red Hat manuals and let them read. They pick up the vocabulary (firewalld, nmcli, SELinux), but they still just "continue text".
② Instruction tuning: show them 2,000 example tickets with model answers. Now they answer questions.
③ QLoRA: instead of rewriting their whole brain (expensive), give them a small notebook of sticky notes they consult on every answer.

2Cleaning the data · Step 1 · TODO 1–4

A PDF is made for printing, not for reading by a model. Extracting it gives you title pages, tables of contents, legal notices that repeat in every manual, and page headers on every page. The model would learn those as if they were knowledge. CS-2 slide 11 shows that big labs run this same pipeline: filter → deduplicate → …

Analogy. Before handing the intern the manuals, you pull out the blank pages, the 24 identical copyright pages, and the one manual that came in German.

Below are 16 "pages". Apply the filters one by one and watch the count:

steppages leftremoved
Why filter pages and not whole PDFs? One manual = one document of ~100 pages. If you drop the whole manual because its title page is short, you lose 99 good pages. Filter pages, then rebuild each document from the pages that survive.

Deduplication: removing copies. Hash (md5): a short fingerprint of a text; same text → same fingerprint, so comparing fingerprints finds exact copies fast. Near-duplicate: almost the same text (one word changed); a hash misses it, and MinHash / Jaccard similarity catch it. langdetect: a Python library that guesses a text's language from its letter patterns.

3Tokens, BOS/EOS and packing · Step 2 · TODO 5–7

The model reads token IDs (numbers), not letters. A tokenizer cuts text into pieces and looks each one up in a fixed vocabulary (Qwen2.5: about 151k entries).

Never train a new tokenizer for CPT. Row 4,512 of the model's embedding table was learned as the meaning of one specific piece, say "fire". A new tokenizer would give 4,512 to something else, and every learned meaning would be scrambled.

The packing demo

Three documents of different lengths. Click through the steps and change the block size:

BOS (beginning of sequence) / EOS (end of sequence): special tokens marking where a document starts and ends. In packing they tell the model "a new document starts here; don't continue the old one". Qwen detail: its tokenizer has no separate BOS, and the config uses <|endoftext|> for both. That is fine, because what the model needs is a boundary marker, and one token can do that job. Padding: filler tokens added so short sequences reach the block length. They cost compute and teach nothing. Parquet: a compact column-based file format, like a CSV that keeps types and compresses well.

hidden size: length of the vector that represents each token inside the model. attention head: one "reader" that looks at the context in its own way; 14 heads each get a 64-number slice of the 896. GQA (grouped-query attention): 14 query heads share just 2 key/value heads to save memory. lm_head (language-model head): the last layer, which turns the 896-number vector into one score per vocabulary entry. That is why its output size must equal vocab_size.

Two things you will notice in the notebook. ① vocab_size (151,936) is bigger than len(tokenizer) (~151,665): the table is padded to a GPU-friendly size, and the extra rows are never used. ② tie_word_embeddings = True: the input embedding table and the lm_head share one matrix (136M numbers), so it is stored once.

5Loss and perplexity · Steps 4–5 · TODO 10–13

Training objective: predict the next token. Labels = the input itself, shifted by one (the library does the shift). This is CS-2's teacher forcing: every position is scored in one pass.

Cross-entropy loss = −ln(probability the model gave to the correct next token), averaged over all tokens. Perplexity = eloss. Drag the slider:

perplexity = e^loss13

Analogy. Perplexity 13 means the model is as unsure as someone picking between 13 equally likely words. After reading the manuals, on manual text it should be choosing between fewer: lower perplexity.

What a healthy CPT loss curve looks like

Learning rate (LR): how big a step the optimiser takes each update. Warmup: start with a tiny LR and ramp up so early steps don't shock the model. Cosine schedule: after warmup, the LR glides down like half a cosine wave (CS-2 slide 20). Plateau: where the curve flattens, so more steps on this data give little. Callback: a function the Trainer calls at set moments; yours records the loss at every log step (TODO 11). Held-out set: data kept aside and never trained on, used for honest evaluation.

6Catastrophic forgetting · Step 5B · TODO 14

When you update weights on Linux manuals only, the same weights also stored "Paris is the capital of France". Push too hard and that gets overwritten (CS-2 slide 19).

Analogy. Cramming one subject all night for an exam. You ace it, then can't remember your neighbour's name.

Fixes (from the assignment and CS-2): lower the LR (10× is a common step), halve the steps, or mix some general text back in. Mixing general text back in is called replay.

9LoRA: train a tiny add-on, not the whole model · B2 · TODO 17

  
A weight matrix W (d × k) is frozen. LoRA learns the change as two thin matrices: B (d × r) and
  A (r × k). New output: h = W·x + (α/r)·B·A·x (CS-3 slides 14–18). B starts at zero, so at step 0 the model is unchanged.

  
Analogy. Instead of reprinting a 900-page manual, you add a few sticky notes. r (rank) = how many
  sticky notes. α (alpha) = how loudly the notes are read out. The scale α/r keeps that volume steady when you change r.

104-bit quantization and QLoRA

  
Quantization = storing each weight with fewer bits (CS-3 slide 20). QLoRA = the frozen base in 4-bit NF4,
  the LoRA matrices in 16-bit. For each matrix multiply, the weights are expanded back to 16-bit on the fly (CS-3 slides 21–22).

  
Analogy. A photo saved with 16 colours instead of millions. It is much smaller and still clearly recognisable,
  because you only look at it (frozen) and never paint on it.

T4 rule (CS-3 slide 22): the T4 has no bfloat16, so the compute dtype is float16. The notebook
  chooses automatically with BF16_OK. NF4 (NormalFloat-4) places its 16 levels where bell-curve-shaped weights are
  densest, so it loses less information than evenly spaced levels. Double quantization also compresses the scale numbers that NF4 stores.
