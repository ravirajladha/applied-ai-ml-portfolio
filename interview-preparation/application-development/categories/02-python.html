SECTION 1

Python for someone who already writes Java and TypeScript

The JD lists Python first. This is the biggest genuine gap, and also the fastest one to close — you are not learning to program, only learning a different set of habits.

PrimerWhat is actually different from Java

You already know loops, objects, exceptions and interfaces. Python changes four things about how you express them, and almost every mistake a Java developer makes in Python comes from one of these four.

1. Indentation is the syntax

No braces, no semicolons. A colon opens a block and indentation defines it. Four spaces, consistently. This feels alarming for a week and then becomes invisible.

def classify(score):
    if score >= 80:
        return "good"
    elif score >= 50:
        return "fair"
    return "poor"

2. Types are dynamic, but annotations are expected

A variable has no declared type and can be reassigned to anything. But modern professional Python is annotated — you write the types, and tools like mypy check them. The annotations are not enforced at runtime; they are documentation the tooling can verify. Write them. Unannotated Python in an interview reads as hobby code.

def average_score(scores: list[float]) -> float:
    return sum(scores) / len(scores)

3. Functions are objects, and that unlocks a lot

You can pass a function, return one, and store one in a dict. That is what makes decorators possible — and decorators are everywhere in Python frameworks (@app.get(...), @pytest.fixture). Conceptually a decorator is Java's annotation plus the interceptor that reads it, collapsed into one mechanism you can write yourself.

4. There is one obvious way to do it, and it is called "Pythonic"

Python has strong idiom. Writing correct-but-Java-shaped Python is the most visible tell in an interview. The three that matter most:

Java habitPythonic
for (int i = 0; i < list.size(); i++)for item in items: — and enumerate(items) if you need the index
Build a list with a loop and .add()[f(x) for x in items if cond(x)]
Open a resource, use it, close it in finallywith open(path) as f: — the context manager closes it for you

Q1List, tuple, set, dict — when do you use each?▼
TypeLiteralPropertiesUse for
list[1, 2, 3]Ordered, mutable, duplicates allowed. Index O(1), in is O(n)An ordered collection you will change
tuple(1, 2)Ordered, immutable, hashableA fixed record; returning several values; a dict key

The performance answer they are fishing for: checking membership against a list is O(n). If you are doing it inside a loop, convert to a set first and the whole thing goes from O(n·m) to O(n+m). This is one of the most common real Python performance bugs.
valid_ids = {row.id for row in reference_rows}   # set, built once
missing = [a for a in assets if a.id not in valid_ids]

Q2Comprehensions, and when a generator is better▼
names   = [a.name for a in assets if a.active]        # list comprehension
by_id   = {a.id: a for a in assets}                   # dict comprehension
sites   = {a.site_id for a in assets}                 # set comprehension
lazy    = (a.name for a in assets if a.active)        # generator — nothing computed yet

A list comprehension builds the whole list in memory immediately. A generator expression (round brackets) produces items one at a time, on demand, holding one at a time in memory.

Use a generator when the source is large or infinite, when you only need to iterate once, or when you are streaming — reading a multi-gigabyte CSV, for instance. Use a list when you need to index it, take its length, or iterate more than once.

def read_rows(path):
    with open(path) as f:
        for line in f:                 # the file object is itself a generator
            yield parse(line)          # yield makes this a generator function

total = sum(r.volume for r in read_rows("huge.csv"))   # constant memory
Trap: a generator is exhausted after one pass. Iterating it a second time yields nothing — silently, with no error. If you need it twice, materialise it with list().

Q3The mutable default argument — Python's most famous trap▼
def add_tag(tag, tags=[]):      # WRONG
    tags.append(tag)
    return tags

add_tag("a")   # ['a']
add_tag("b")   # ['a', 'b']  — the same list, still there

Default arguments are evaluated once, when the function is defined, not on each call. So every call shares one list. In a long-running web application this is a data leak between requests.

def add_tag(tag, tags: list[str] | None = None):   # right
    tags = [] if tags is None else tags
    tags.append(tag)
    return tags

Q4is vs ==, and shallow vs deep copy▼

== compares value (it calls __eq__). is compares identity — are these the same object in memory. Use is only for None, True and False.

From your Java world → exactly the equals() vs == distinction, with the operators swapped round. In Java == is identity; in Python == is value. Easy to get backwards under pressure.
import copy
shallow = copy.copy(original)        # new outer object, same nested objects
deep    = copy.deepcopy(original)    # everything recursively duplicated
sliced  = original[:]                # shallow copy of a list

A shallow copy of a list of dicts gives you a new list pointing at the same dicts — mutating one still affects the original. That surprises people in tests especially.

Q5*args and **kwargs▼

*args collects extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dict. The asterisks are the syntax; the names are convention.

def log_event(name, *tags, **fields):
    print(name, tags, fields)

log_event("deploy", "prod", "api", duration=12.4, user="ravi")
# deploy ('prod', 'api') {'duration': 12.4, 'user': 'ravi'}

You will meet them most often when writing a decorator that must forward whatever arguments the wrapped function takes.

Also know keyword-only arguments: anything after a bare * in the signature must be passed by name. Good API design for booleans — def export(data, *, include_archived=False) forces callers to write include_archived=True instead of a mystery True.

Q6Decorators — what they are and how to write one▼

A decorator is a function that takes a function and returns a replacement for it. @timed above a definition is just sugar for my_func = timed(my_func).

import functools, time

def timed(func):
    @functools.wraps(func)                # preserves __name__ and docstring
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = (time.perf_counter() - start) * 1000
            logger.info("call.timed", extra={"fn": func.__name__, "ms": elapsed})
    return wrapper

@timed
def score_asset(asset_id: int) -> float:
    ...

Why frameworks use them: cross-cutting concerns — routing, caching, retries, authorisation, transactions — attach to a function without editing its body.

Always use functools.wraps. Without it the wrapper replaces the function's name, docstring and signature, which breaks introspection — and in FastAPI it breaks the generated OpenAPI documentation. This is a genuine "have you actually written one?" tell.
From your Java world → a decorator is the same concept as a Spring AOP aspect or a TestNG listener, expressed in the language rather than by the container.

Q7Classes, self, inheritance and the dunder methods worth knowing▼
class Asset:
    def __init__(self, asset_id: int, name: str, score: float = 0.0):
        self.asset_id = asset_id          # instance attributes; no declarations needed
        self.name = name
        self._score = score               # single underscore = "internal by convention"

    @property                             # exposes a method as an attribute
    def condition(self) -> str:
        return "good" if self._score >= 80 else "needs review"

    def __repr__(self) -> str:            # what you see in logs and the debugger
        return f"Asset(id={self.asset_id}, name={self.name!r})"

    def __eq__(self, other) -> bool:
        return isinstance(other, Asset) and self.asset_id == other.asset_id
  • self is the explicit receiver — Java's implicit this, written out. It is always the first parameter of an instance method.
  • No private. A leading underscore is a convention meaning "do not touch"; a double underscore triggers name-mangling but is still reachable. Python's position is that consenting adults do not need enforcement.
  • @property turns a method into a computed attribute, so asset.condition reads like a field. This is why Python does not need boilerplate getters.
  • @staticmethod takes no receiver; @classmethod takes the class and is the idiomatic way to write alternative constructors.
If asked about multiple inheritance: Python allows it and resolves the order with the MRO (method resolution order, C3 linearisation), inspectable via Class.__mro__. In application code, prefer composition; mixins are the one genuinely common use.

Q9Exceptions, and the with statement▼
class AssetNotFound(Exception):
    """Raised when an asset id does not exist."""

try:
    asset = repo.get(asset_id)
except AssetNotFound:
    raise HTTPException(status_code=404, detail="asset not found")
except (TimeoutError, ConnectionError) as exc:
    logger.warning("upstream.unavailable", exc_info=exc)
    raise
else:
    audit.record(asset)        # runs only if no exception was raised
finally:
    metrics.increment("asset.lookup")   # always runs

Python's culture is EAFP — "easier to ask forgiveness than permission". Try the operation and catch the failure, rather than checking preconditions first. It avoids a race between the check and the use.

Context managers
with open(path) as f, session.begin():     # both cleaned up, in reverse order
    process(f)

with guarantees cleanup even on an exception — the equivalent of Java's try-with-resources. Anything with __enter__ and __exit__ works, including database sessions, locks and temporary directories, and you can write your own in four lines with @contextlib.contextmanager.

Never write a bare except: — it swallows KeyboardInterrupt and SystemExit too, making the process un-killable. Use except Exception: at worst.

Q11The GIL: threading vs multiprocessing vs asyncio▼

The Global Interpreter Lock means only one thread executes Python bytecode at a time in a CPython process. Threads still help with I/O, because the lock is released while waiting on the network or disk — but they give you no CPU parallelism.

WorkloadUseWhy
I/O-bound (HTTP calls, database, files)asyncio, or threadsThe waiting is the cost, and asyncio waits thousands of things on one thread cheaply
CPU-bound (parsing, numeric work)multiprocessingSeparate processes have separate interpreters, so true parallelism
Numeric arraysNumPy / pandasThe heavy loop runs in C and releases the GIL anyway
Web servingMultiple worker processesUvicorn/Gunicorn run N workers; each has its own GIL
The mature framing: "In a web application the GIL is rarely the constraint, because we scale with processes and containers rather than threads, and the workload is I/O-bound anyway. It matters the moment you put CPU-heavy work — like model inference or a big transformation — on the request thread."

Q12asyncio: async, await, and the mistake everyone makes▼
import asyncio, httpx

async def fetch_site(client, site_id: int) -> dict:
    r = await client.get(f"/sites/{site_id}")
    return r.json()

async def fetch_all(site_ids: list[int]) -> list[dict]:
    async with httpx.AsyncClient(base_url=BASE, timeout=5.0) as client:
        # concurrent — all requests in flight at once
        return await asyncio.gather(*(fetch_site(client, i) for i in site_ids))
The mistake: awaiting inside a loop. for i in ids: await fetch_site(client, i) is fully sequential — you have written async code that behaves synchronously. Twenty calls at 200 ms each take four seconds instead of 200 ms. This is the single most likely async follow-up question.
The second mistake: calling a blocking library inside an async def. One synchronous requests.get() or a heavy CPU loop blocks the entire event loop and every other request the process is serving. Use an async client, or push the blocking work to a thread with asyncio.to_thread(...).
From your TypeScript world → the model is identical to Node's event loop, and asyncio.gather is Promise.all. You already understand this; only the keywords change.

Q13Modules, packages, imports and if __name__ == "__main__"▼

A module is a .py file. A package is a directory of modules (traditionally with an __init__.py). Imports are resolved against sys.path.

from asset_api.services.scoring import score_asset   # absolute — always prefer this
from .scoring import score_asset                     # relative — within a package only

if __name__ == "__main__":
    main()

That last idiom exists because importing a module executes it. Without the guard, importing a file would run its script body as a side effect. The check means "only run this when the file is executed directly, not when it is imported."

Circular imports are the common failure: A imports B and B imports A. Usually a design smell — the shared thing belongs in a third module. If you truly need it, move the import inside the function.

Q16A FastAPI service you can write on a whiteboard▼
from fastapi import FastAPI, Depends, HTTPException, status
from pydantic import BaseModel, Field
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    database_url: str                     # read from the DATABASE_URL env var
    log_level: str = "INFO"

settings = Settings()
app = FastAPI(title="Asset API", version="1.0.0")

class AssetIn(BaseModel):
    name: str = Field(min_length=1, max_length=120)
    site_id: int
    condition_score: float = Field(ge=0, le=100)

class AssetOut(AssetIn):
    id: int

def get_repo() -> AssetRepository:        # dependency; overridden in tests
    return AssetRepository(settings.database_url)

@app.get("/health")
async def health():
    return {"status": "ok"}

@app.get("/v1/assets", response_model=list[AssetOut])
async def list_assets(site_id: int, limit: int = 50, offset: int = 0,
                      repo: AssetRepository = Depends(get_repo)):
    return await repo.list(site_id=site_id, limit=min(limit, 200), offset=offset)

@app.post("/v1/assets", response_model=AssetOut, status_code=status.HTTP_201_CREATED)
async def create_asset(payload: AssetIn, repo: AssetRepository = Depends(get_repo)):
    if await repo.exists(payload.name, payload.site_id):
        raise HTTPException(status.HTTP_409_CONFLICT, "asset already exists")
    return await repo.insert(payload)
What to say while you write it
  • The Pydantic model gives request validation and a 422 with field-level errors for free — no manual checking.
  • response_model filters the output, so an internal field cannot leak.
  • Depends is FastAPI's dependency injection. In tests you call app.dependency_overrides[get_repo] = fake_repo and never touch a database.
  • Settings come from environment variables via BaseSettings — twelve-factor config, not a hard-coded connection string.
  • min(limit, 200) — always cap a client-supplied page size, or someone asks for a million rows.
  • The /health endpoint is what the platform probes to decide whether to send you traffic.
The bonus point: FastAPI serves interactive documentation at /docs generated from these annotations. Mention that it means the API contract is always current — a genuine argument you can make in a design discussion.

Q17Middleware, background tasks and startup in FastAPI▼
from contextlib import asynccontextmanager
import uuid

@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.pool = await create_pool(settings.database_url)   # startup
    yield
    await app.state.pool.close()                                # shutdown

app = FastAPI(lifespan=lifespan)

@app.middleware("http")
async def correlation_id(request, call_next):
    cid = request.headers.get("X-Correlation-Id", str(uuid.uuid4()))
    response = await call_next(request)
    response.headers["X-Correlation-Id"] = cid
    return response

@app.post("/v1/reports")
async def request_report(payload: ReportIn, tasks: BackgroundTasks):
    report_id = await repo.create_pending(payload)
    tasks.add_task(generate_report, report_id)     # returns immediately
    return {"id": report_id, "status": "processing"}
Know the limit of background tasks. They run in the same process, so if it restarts mid-task the work is lost silently. Fine for sending an email; not fine for anything that must not be lost. For that, put a message on a queue (Service Bus) and have a separate worker consume it. Volunteering that distinction is a strong architectural signal.

Q18SQLAlchemy: sessions, the ORM, and N+1▼
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship, selectinload
from sqlalchemy import select

class Base(DeclarativeBase): pass

class Site(Base):
    __tablename__ = "sites"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str]
    assets: Mapped[list["Asset"]] = relationship(back_populates="site")

class Asset(Base):
    __tablename__ = "assets"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(index=True)
    site_id: Mapped[int] = mapped_column(ForeignKey("sites.id"))
    site: Mapped[Site] = relationship(back_populates="assets")

# N+1: one query for sites, then one per site when .assets is touched
stmt = select(Site).where(Site.region == "north")

# fixed: load the children in a second batched query
stmt = select(Site).where(Site.region == "north").options(selectinload(Site.assets))

A session is a unit of work: it tracks the objects you have loaded, batches changes, and commits them in one transaction. Scope it per request — a session shared across requests leaks data between users and holds a connection open.

Also mention Alembic for schema migrations — versioned, reviewable, applied in the deployment pipeline. "How do you change a database schema safely?" is a common follow-up, and the answer is migrations plus the expand/contract pattern.
Coming from test automation → you have almost certainly seen an endpoint firing hundreds of queries during a load test. That is the story to tell here.

Q21Live coding: the Python problems that actually get set▼

Mid-level interviews rarely ask for dynamic programming. They ask for string and collection manipulation written idiomatically, because that is what the job is.

# 1. Count occurrences
from collections import Counter
Counter(words).most_common(3)

# 2. Group records by a key
from collections import defaultdict
by_site = defaultdict(list)
for a in assets:
    by_site[a.site_id].append(a)

# 3. First non-repeating character
def first_unique(s: str) -> str | None:
    counts = Counter(s)
    return next((c for c in s if counts[c] == 1), None)

# 4. Reverse the words of a sentence
" ".join(reversed(sentence.split()))

# 5. Two numbers summing to a target, in one pass
def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    seen: dict[int, int] = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return seen[target - n], i
        seen[n] = i
    return None

# 6. Flatten a nested list
[x for row in matrix for x in row]

# 7. Deduplicate, preserving order
list(dict.fromkeys(items))

# 8. Merge two dicts, second wins
merged = base | override
What is being marked: whether you reach for the standard library (Counter, defaultdict, enumerate, zip, any/all) instead of hand-rolling. Also: say your complexity out loud when you finish, and name one edge case (empty input, duplicates, None) without being asked.

Q22pandas and NumPy — enough to be credible near data work▼

The JD mentions working with data engineers and scientists. You do not need to be a pandas expert; you need to not be lost when someone hands you a notebook.

import pandas as pd

df = pd.read_csv("readings.csv", parse_dates=["recorded_at"])
df = df[df["sensor_id"].notna()]                       # filter rows
df["is_high"] = df["value"] > threshold                # derived column
daily = (df.groupby([df["recorded_at"].dt.date, "site_id"])["value"]
           .agg(["mean", "max", "count"])
           .reset_index())
merged = daily.merge(sites, on="site_id", how="left")  # a SQL join

The mental model that makes pandas click: a DataFrame is a table and the operations are SQL. groupby is GROUP BY, merge is JOIN, boolean indexing is WHERE. Operations are vectorised — applied to the whole column in C — so a Python for loop over rows is typically 50–100× slower and is the thing to flag in a review.

The engineering opinion worth having: pandas is excellent for analysis and for data that fits in memory. Production pipelines over larger data belong in Spark or in the database. Knowing where that line is matters more than knowing the API.

Q23How would you find and fix a slow Python endpoint?▼
  1. Measure before guessing. cProfile for CPU, and a distributed trace (Application Insights / OpenTelemetry) to see where wall-clock time goes.
  2. Count the queries. Turn on SQLAlchemy echo or the query log. N+1 is the most common cause by a wide margin.
  3. Look for blocking calls in async code — a synchronous HTTP client or file read inside async def stalls the whole event loop.
  4. Look for sequential awaits that should be asyncio.gather.
  5. Check serialisation volume — returning 10,000 rows because there is no pagination costs more in JSON encoding than in the query.
  6. Then consider caching and, only then, the algorithm.
Coming from test automation → this is a performance-testing answer. Lead with "I'd want a profile and a trace before changing anything" — the instinct not to guess is exactly what they are testing.

QuestionAnswer
Is Python pass-by-value or pass-by-reference?Neither — pass by object reference. Rebinding a parameter inside a function does not affect the caller; mutating a mutable object does.
list vs tuple — why does immutability matter?Tuples are hashable, so they can be dict keys and set members. Lists cannot.
What does len() call?__len__. Python's built-ins delegate to dunder methods — that is the data model, and it is how your own classes integrate with the language.
Difference between append and extend?append adds one item (a list becomes a nested list); extend adds each item of an iterable.
What is a closure?A function that captures variables from the scope it was defined in. Decorators rely on it.
Why is string concatenation in a loop bad?Strings are immutable, so each += builds a new string — O(n²). Use "".join(parts).
@staticmethod vs @classmethod?Static takes no receiver; class takes the class, which makes it the right way to write alternative constructors and to work correctly with subclasses.
