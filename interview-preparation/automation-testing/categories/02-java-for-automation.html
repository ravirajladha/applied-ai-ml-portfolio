Q43Abstraction vs Encapsulation — they sound the same. What is the actual difference?▼
  • Abstraction solves a problem at design level: what should be exposed. Achieved with interfaces and abstract classes. It hides complexity/implementation.
  • Encapsulation solves it at implementation level: how to protect the exposed thing. Achieved with access modifiers and getters/setters. It hides data.

One-liner: abstraction hides the implementation; encapsulation hides the data. A TV remote is abstraction (you press "volume up", not knowing the circuitry). The sealed plastic casing with screws is encapsulation.

Q45Interface vs Abstract class. When do you choose which?▼

Multiple inheritanceA class can implement manyOnly one can be extended

The decision rule

"Do the implementations share state and code? → abstract class. Do unrelated classes need to share a contract? → interface." In practice both are used together: WebDriver is an interface (contract), and RemoteWebDriver is a class implementing it that ChromeDriver extends.

Java 8 follow-up: "If interfaces have default methods now, why keep abstract classes?" Because interfaces still cannot hold instance state or constructors. And the diamond problem with two conflicting default methods must be resolved explicitly: InterfaceA.super.method();

Q46What does static mean? Why should the WebDriver not be static?▼

static members belong to the class, not to an instance — one copy shared by everyone, loaded when the class is loaded, accessible without creating an object.

  • static variable — shared counter, config values.
  • static method — utility functions (ConfigReader.get("url")). Cannot use this or instance members directly.
  • static block — runs once when the class loads; used to initialise static config.
  • static nested class — used in the Builder pattern.
The important interview answer: a static WebDriver driver; works fine until you run tests in parallel. Then all threads share one browser instance: thread A navigates while thread B is asserting, and you get random NoSuchElementExceptions and impossible failures. The correct solution is ThreadLocal<WebDriver> — a static holder that gives each thread its own value (see Q61).
// WRONG for parallel execution
public static WebDriver driver;

// RIGHT
private static final ThreadLocal<WebDriver> DRIVER = new ThreadLocal<>();
public static WebDriver get()            { return DRIVER.get(); }
public static void set(WebDriver d)      { DRIVER.set(d); }
public static void unload()              { DRIVER.remove(); }   // avoid memory leak

Q47final vs finally vs finalize.▼
  • final — a modifier. final variable = constant (cannot be reassigned; the object it points to can still mutate). final method = cannot be overridden. final class = cannot be extended (e.g. String).
  • finally — a block that always executes after try/catch, whether or not an exception was thrown. Used for cleanup: driver.quit(), closing streams and DB connections. It runs even if the try block has a return. (It does not run if the JVM exits via System.exit() or the thread is killed.)
  • finalize() — a legacy Object method the garbage collector might call before reclaiming an object. Unpredictable, deprecated since Java 9, never rely on it. Use try-with-resources / AutoCloseable instead.
try (BufferedReader br = new BufferedReader(new FileReader("data.csv"))) {
    return br.readLine();                  // resource auto-closed, no finally needed
} catch (IOException e) {
    throw new FrameworkException("Could not read test data", e);
}

Q48String vs StringBuilder vs StringBuffer. Why is String immutable?▼

Why immutable?
  • String pool — identical literals share one object in the heap's string pool, saving huge memory. That is only safe if nobody can mutate them.
  • Security — file paths, DB URLs and credentials are passed as Strings; immutability prevents a reference being changed after a security check.
  • Thread safety for free, and a cached hashCode() which makes String an ideal HashMap key.
String a = "qa";            // goes to the string pool
String b = "qa";            // same pooled object  -> a == b is true
String c = new String("qa");// new heap object     -> a == c is FALSE
System.out.println(a.equals(c)); // true — always compare with equals()

Q49== vs equals(), and the equals/hashCode contract.▼
  • == compares references for objects (do both variables point to the same memory?) and values for primitives.
  • equals() compares content, if the class overrides it. The default Object.equals() is just ==.
The contract

If a.equals(b) is true, then a.hashCode() == b.hashCode() must be true. The reverse is not required (unequal objects may share a hash — a collision). If you override equals() you must override hashCode(), otherwise your object will "disappear" inside a HashMap/HashSet: it is stored in bucket A, and the lookup goes to bucket B.

Integer x = 127, y = 127;   System.out.println(x == y); // true  (Integer cache -128..127)
Integer p = 128, q = 128;   System.out.println(p == q); // false (outside the cache!)

Q52How does HashMap work internally?▼
  1. A HashMap holds an array of buckets (default capacity 16, load factor 0.75).
  2. On put(k,v) it calls k.hashCode(), applies a supplemental hash (spreads the high bits), and computes the index as hash & (n-1).
  3. If the bucket is empty → store a new Node. If occupied (a collision) → walk the chain comparing with hashCode() then equals(). If an equal key exists, the value is replaced; otherwise the node is appended.
  4. When a bucket's chain exceeds 8 nodes (and capacity ≥ 64), Java 8+ converts that chain into a balanced red-black tree, improving worst-case lookup from O(n) to O(log n). It reverts to a list below 6 nodes.
  5. When size > capacity × loadFactor (12 for the default 16), the map resizes to double capacity and rehashes all entries — an expensive operation, which is why you pre-size a map when you know the volume.
Follow-up: "What if you use a mutable object as a key and then change it?" Its hashCode changes, so it now maps to a different bucket — the entry becomes unreachable (a memory leak that get() can never find). That is exactly why String is immutable and is the preferred key type.

Q53Explain exception handling: checked vs unchecked, throw vs throws, and custom exceptions.▼

Hierarchy: Throwable → Error (JVM problems: OutOfMemoryError, StackOverflowError — do not catch) and Exception → RuntimeException (unchecked) and everything else (checked).

  • Checked — the compiler forces you to handle or declare them. IOException, SQLException, InterruptedException. They represent recoverable, expected external failures.
  • Unchecked — NullPointerException, ArrayIndexOutOfBoundsException, IllegalArgumentException, and all Selenium exceptions (they extend WebDriverException → RuntimeException). That's why you are not forced to try/catch findElement.
  • throw — actually throws an instance: throw new FrameworkException("msg");. throws — declares in the method signature that the caller must deal with it.
public class FrameworkException extends RuntimeException {
    public FrameworkException(String message, Throwable cause) { super(message, cause); }
}

// Wrap low-level failures with business context — this is what makes
// a failed CI run debuggable at 2 a.m.
public void uploadInvoice(Path file) {
    try {
        driver.findElement(By.id("file")).sendKeys(file.toAbsolutePath().toString());
    } catch (NoSuchElementException e) {
        throw new FrameworkException("Upload control missing on Invoice page. URL="
                + driver.getCurrentUrl(), e);   // keep the cause, never swallow it
    }
}
Never write an empty catch block in a test framework. A swallowed exception turns a real failure into a silent false PASS — which is worse than no test at all. If you must ignore one, log it and comment why.

Q54Can you have try without catch? What is multi-catch and try-with-resources? Does finally always run?▼
  • try without catch — yes, if there is a finally (or it is try-with-resources). try { } finally { } is legal.
  • Multi-catch (Java 7+): catch (NoSuchElementException | TimeoutException e) — the variable is implicitly final. Catch blocks must go from most specific to most general, or the compiler errors.
  • try-with-resources — any object implementing AutoCloseable declared in the parentheses is closed automatically in reverse order, even on exception. Cleaner than a finally block.
  • Does finally always run? Almost always — including when try returns. Exceptions: System.exit(), JVM crash, infinite loop or thread kill inside try, or a power failure.
public int demo() {
    try { return 1; }            // value 1 is computed and held
    finally { System.out.println("always runs"); }   // prints, then 1 is returned
}
// Warning: a `return` inside finally would OVERRIDE the try's return and
// swallow any pending exception — never do that.

Q55Java 8 features you actually use in automation — lambdas, functional interfaces, streams.▼
  • Lambda expression — an anonymous implementation of a functional interface: (a, b) -> a + b. Selenium's ExpectedCondition and FluentWait take one.
  • Functional interface — an interface with exactly one abstract method, marked @FunctionalInterface. Built-ins: Predicate<T> (T→boolean), Function<T,R>, Consumer<T> (T→void), Supplier<T> (→T), BiFunction.

  • Method reference — WebElement::getText instead of e -> e.getText().
  • Optional, default methods, new Date/Time API (LocalDate, Duration — used everywhere in modern Selenium waits).

Q56What is Optional and how does it help?▼

A container that may or may not hold a non-null value. It makes "this might be absent" part of the type signature instead of an undocumented surprise, which reduces NullPointerExceptions.

Optional<WebElement> banner = driver.findElements(By.id("promo")).stream().findFirst();
banner.ifPresent(WebElement::click);                       // do only if present
String text = banner.map(WebElement::getText).orElse("");  // safe default
WebElement el = banner.orElseThrow(() -> new FrameworkException("Promo banner missing"));
Do not call .get() without checking isPresent() — that just recreates the NPE with extra steps. And do not use Optional for method parameters or entity fields; it is designed for return types.

Q57What are Generics and why do they matter in a framework?▼

Generics give compile-time type safety and remove casting. List<String> cannot accidentally receive an Integer. Java implements them via type erasure — the type parameter is removed at compile time, which is why you cannot do new T[] or instanceof List<String>.

// A generic page-navigation helper: returns the page object you asked for
public <T extends BasePage> T navigateTo(Class<T> pageClass) {
    try {
        return pageClass.getDeclaredConstructor(WebDriver.class).newInstance(driver);
    } catch (Exception e) {
        throw new FrameworkException("Cannot instantiate " + pageClass.getSimpleName(), e);
    }
}
// Usage — fully type-safe, no cast:
LoginPage login = navigateTo(LoginPage.class);

Wildcards: <? extends T> = read-only "producer"; <? super T> = write "consumer". Mnemonic PECS — Producer Extends, Consumer Super.

Q59Constructor rules, this vs super, and constructor chaining.▼
  • A constructor has the class's name, no return type, and runs on object creation. If you write none, Java gives a no-arg default — but only if you declared no constructor at all.
  • Constructors can be overloaded but never overridden or inherited.
  • this(...) calls another constructor of the same class; super(...) calls the parent's. Either must be the first statement, and you cannot use both.
  • If you don't write super(...), the compiler inserts an implicit super(). So the parent is always constructed first.
public class BasePage {
    protected WebDriver driver;
    protected WebDriverWait wait;
    public BasePage(WebDriver driver) { this(driver, 20); }        // this()
    public BasePage(WebDriver driver, int timeoutSec) {
        this.driver = driver;                                       // shadowing resolved by this.
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(timeoutSec));
        PageFactory.initElements(driver, this);
    }
}
public class CartPage extends BasePage {
    public CartPage(WebDriver driver) { super(driver, 45); }        // super()
}

Q60Implement a thread-safe Singleton. Where do you use it in a framework?▼

Singleton = exactly one instance for the whole JVM, with a global access point. In frameworks: config reader, logger, extent-report manager, DB connection pool.

// 1. Bill Pugh (holder idiom) — lazy, thread-safe, no synchronization cost
public class ExtentManager {
    private ExtentManager() { }
    private static class Holder {
        static final ExtentReports INSTANCE = build();
    }
    public static ExtentReports get() { return Holder.INSTANCE; }
    private static ExtentReports build() { /* configure reporter */ return new ExtentReports(); }
}

// 2. Double-checked locking — needs `volatile`, or another thread can see
//    a half-constructed object due to instruction reordering
public class Config {
    private static volatile Config instance;
    private Config() { }
    public static Config get() {
        if (instance == null) {
            synchronized (Config.class) {
                if (instance == null) instance = new Config();
            }
        }
        return instance;
    }
}

// 3. Enum singleton — simplest, serialization- and reflection-safe (Joshua Bloch's pick)
public enum Env { INSTANCE; public String baseUrl() { return "https://qa.example.com"; } }
Very common follow-up: "Should the WebDriver be a singleton?" No. A singleton means one driver for the whole JVM, which breaks parallel execution. Use a ThreadLocal-backed factory instead — conceptually "one instance per thread", not "one per JVM".

Q61What is ThreadLocal and why is it essential for parallel Selenium execution?▼

ThreadLocal<T> gives every thread its own independently initialised copy of a variable. Internally each Thread object carries a ThreadLocalMap keyed by the ThreadLocal instance — so get() returns the calling thread's value.

In TestNG parallel mode, each test method runs on its own thread. Each thread must drive its own browser, but the page objects and utilities need to reach "the driver" without passing it through every method signature. ThreadLocal solves exactly that.

public final class DriverFactory {
    private static final ThreadLocal<WebDriver> TL = new ThreadLocal<>();

    public static void init(String browser) {
        WebDriver driver = switch (browser.toLowerCase()) {
            case "firefox" -> new FirefoxDriver();
            case "edge"    -> new EdgeDriver();
            default        -> new ChromeDriver();
        };
        driver.manage().window().maximize();
        TL.set(driver);
    }
    public static WebDriver get() {
        WebDriver d = TL.get();
        if (d == null) throw new IllegalStateException("Driver not initialised for thread "
                + Thread.currentThread().getName());
        return d;
    }
    public static void quit() {
        WebDriver d = TL.get();
        if (d != null) { d.quit(); TL.remove(); }   // remove() prevents a memory leak
    }
}
Always call TL.remove() in teardown. Thread pools reuse threads; if you don't remove, the stale driver reference stays attached to the pooled thread and leaks memory (and the next test may grab a dead driver).

Q62Basic multithreading: thread lifecycle, synchronized, and why Thread.sleep() is bad in tests.▼

Lifecycle: New → Runnable → Running → (Blocked / Waiting / Timed-waiting) → Terminated.

  • Creating a thread: extend Thread, or implement Runnable/Callable (preferred — leaves your inheritance slot free) and submit to an ExecutorService.
  • synchronized — a lock ensuring only one thread executes a block/method on that monitor at a time. Prevents race conditions on shared mutable state (e.g. a shared report or a counter).
  • wait()/notify() vs sleep(): wait() releases the lock, sleep() does not.
Why Thread.sleep() is an anti-pattern in tests: it is a fixed unconditional pause. On a fast run it wastes seconds (a 200-test suite with 3s sleeps wastes 10 minutes per run); on a slow run 3s isn't enough and the test fails anyway. It converts a deterministic wait into a gamble. Use explicit/fluent waits (Selenium) or auto-waiting assertions (Playwright). The only defensible use is a documented workaround for an animation with no observable end state.

Q63How do you read test data from Excel, CSV, JSON and properties files in Java?▼
// ---- Excel with Apache POI ----
public static List<Map<String,String>> readSheet(String path, String sheetName) {
    List<Map<String,String>> rows = new ArrayList<>();
    try (FileInputStream fis = new FileInputStream(path);
         Workbook wb = new XSSFWorkbook(fis)) {              // XSSF = .xlsx, HSSF = .xls
        Sheet sheet = wb.getSheet(sheetName);
        Row header = sheet.getRow(0);
        DataFormatter fmt = new DataFormatter();             // reads any cell type as String
        for (int r = 1; r <= sheet.getLastRowNum(); r++) {
            Row row = sheet.getRow(r);
            if (row == null) continue;
            Map<String,String> map = new LinkedHashMap<>();
            for (int c = 0; c < header.getLastCellNum(); c++) {
                map.put(fmt.formatCellValue(header.getCell(c)),
                        fmt.formatCellValue(row.getCell(c)));
            }
            rows.add(map);
        }
    } catch (IOException e) { throw new FrameworkException("Excel read failed: " + path, e); }
    return rows;
}

Q64Coding round: string questions they actually ask (reverse, palindrome, duplicates, vowels).▼
// 1. Reverse a string WITHOUT StringBuilder.reverse()
public static String reverse(String s) {
    char[] c = s.toCharArray();
    for (int i = 0, j = c.length - 1; i < j; i++, j--) {
        char t = c[i]; c[i] = c[j]; c[j] = t;
    }
    return new String(c);
}

// 2. Palindrome check, ignoring case and non-alphanumerics
public static boolean isPalindrome(String s) {
    String clean = s.replaceAll("[^A-Za-z0-9]", "").toLowerCase();
    return clean.equals(new StringBuilder(clean).reverse().toString());
}

// 3. Reverse the WORDS of a sentence ("I love QA" -> "QA love I")
public static String reverseWords(String s) {
    String[] w = s.trim().split("\\s+");
    Collections.reverse(Arrays.asList(w));
    return String.join(" ", w);
}

// 4. First non-repeating character
public static Character firstUnique(String s) {
    Map<Character,Integer> count = new LinkedHashMap<>();
    for (char c : s.toCharArray()) count.merge(c, 1, Integer::sum);
    return count.entrySet().stream().filter(e -> e.getValue() == 1)
                .map(Map.Entry::getKey).findFirst().orElse(null);
}

// 5. Count duplicate characters
public static Map<Character,Long> duplicates(String s) {
    return s.chars().mapToObj(c -> (char) c)
            .collect(Collectors.groupingBy(c -> c, Collectors.counting()))
            .entrySet().stream().filter(e -> e.getValue() > 1)
            .collect(Collectors.toMap(Map.Entry::getKey, Map.Entry::getValue));
}

// 6. Count vowels and consonants
long vowels = s.toLowerCase().chars().filter(c -> "aeiou".indexOf(c) >= 0).count();

// 7. Are two strings anagrams?
public static boolean isAnagram(String a, String b) {
    char[] x = a.replaceAll("\\s","").toLowerCase().toCharArray();
    char[] y = b.replaceAll("\\s","").toLowerCase().toCharArray();
    Arrays.sort(x); Arrays.sort(y);
    return Arrays.equals(x, y);
}

// 1. Second largest element in an array (single pass, no sorting)
public static int secondLargest(int[] a) {
    int max = Integer.MIN_VALUE, second = Integer.MIN_VALUE;
    for (int n : a) {
        if (n > max)            { second = max; max = n; }
        else if (n > second && n != max) { second = n; }
    }
    if (second == Integer.MIN_VALUE) throw new IllegalArgumentException("No second largest");
    return second;
}

    for (int i = 0; i < n; i++) { long t = a + b; a = b; b = t; }
    return a;
}

public static boolean isPrime(int n) {
    if (n < 2) return false;
    for (int i = 2; i * i <= n; i++) if (n % i == 0) return false;  // only up to sqrt(n)
    return true;
}
