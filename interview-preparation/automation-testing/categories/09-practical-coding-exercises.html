Q231 – Q250 · The live-coding round. Type every one of these by hand at least once — reading them is not the same as producing them under pressure on a shared screen while someone watches.

How to behave in a live-coding round. Say the plan out loud before typing ("I'll find the row by its order id, then scope the button lookup inside that row"). Q231Write the reusable wait/interaction helpers for a BasePage.▼
public abstract class BasePage {
    protected final WebDriver driver;
    protected final WebDriverWait wait;

    protected BasePage(WebDriver driver) {
        this.driver = driver;
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(
                Config.getInt("timeout.explicit")));
    }

    protected WebElement visible(By locator) {
        return wait.until(ExpectedConditions.visibilityOfElementLocated(locator));
    }
    protected WebElement clickable(By locator) {
        return wait.until(ExpectedConditions.elementToBeClickable(locator));
    }
    protected void click(By locator) { clickable(locator).click(); }

    protected void type(By locator, String text) {
        WebElement el = visible(locator);
        el.clear();
        el.sendKeys(text);
    }
    protected String textOf(By locator)   { return visible(locator).getText().trim(); }
    protected boolean isPresent(By locator) { return !driver.findElements(locator).isEmpty(); }

    protected boolean isVisible(By locator, Duration timeout) {
        try {
            new WebDriverWait(driver, timeout)
                .until(ExpectedConditions.visibilityOfElementLocated(locator));
            return true;
        } catch (TimeoutException e) { return false; }
    }

    protected void waitForSpinnerToClear() {
        wait.until(ExpectedConditions.invisibilityOfElementLocated(
                By.cssSelector("[data-testid='loading']")));
    }
}
Point out why this class exists: one wait strategy, one place to change a timeout, and tests that never touch the Selenium API. That reasoning is what's being marked, not the syntax.

Q232Write a method that returns a table cell value given a row identifier and a column name.▼

The single most-asked Selenium coding exercise.

/**
 * Returns the value of {@code columnName} in the row whose any cell equals {@code rowKey}.
 * Works regardless of column order, so it survives the UI adding a column.
 */
public String getCellValue(String rowKey, String columnName) {
    List<WebElement> headers = driver.findElements(By.cssSelector("#orders thead th"));
    int columnIndex = -1;
    for (int i = 0; i < headers.size(); i++) {
        if (headers.get(i).getText().trim().equalsIgnoreCase(columnName)) {
            columnIndex = i;
            break;
        }
    }
    if (columnIndex == -1)
        throw new IllegalArgumentException("Column not found: " + columnName
                + ". Available: " + headers.stream().map(WebElement::getText).toList());

    WebElement row = driver.findElements(By.cssSelector("#orders tbody tr")).stream()
            .filter(r -> r.findElements(By.tagName("td")).stream()
                          .anyMatch(c -> c.getText().trim().equals(rowKey)))
            .findFirst()
            .orElseThrow(() -> new NoSuchElementException("No row containing: " + rowKey));

    return row.findElements(By.tagName("td")).get(columnIndex).getText().trim();
}

// usage
assertEquals(getCellValue("ORD-991", "Status"), "Delivered");
The detail that impresses: looking the column up by name instead of hardcoding td[4]. Say it out loud — "if the team inserts a column, index-based code silently asserts the wrong cell; this doesn't."

Q233Write a helper that selects a value from any dropdown — native or custom.▼
public void selectDropdownValue(By dropdown, String visibleText) {
    WebElement el = clickable(dropdown);

    if ("select".equalsIgnoreCase(el.getTagName())) {          // native <select>
        new Select(el).selectByVisibleText(visibleText);
        return;
    }

    el.click();                                                 // custom widget
    By option = By.xpath("//*[@role='option' or contains(@class,'option')]"
                       + "[normalize-space()=" + quote(visibleText) + "]");
    clickable(option).click();
    wait.until(ExpectedConditions.invisibilityOfElementLocated(
            By.cssSelector("[role='listbox']")));               // wait for it to close
}

/** Safely quotes a value for XPath, including values containing an apostrophe. */
private static String quote(String value) {
    if (!value.contains("'"))  return "'" + value + "'";
    if (!value.contains("\"")) return "\"" + value + "\"";
    return "concat('" + value.replace("'", "',\"'\",'") + "')";
}
The quote() helper is a genuine senior touch — a customer named O'Brien breaks naive XPath string concatenation, and almost nobody handles it. Mention it even if you don't write the full implementation.

Q234Write a stale-safe click with retry.▼
public void safeClick(By locator) {
    int attempts = 0;
    while (attempts < 3) {
        try {
            clickable(locator).click();
            return;
        } catch (StaleElementReferenceException e) {
            attempts++;                                   // DOM re-rendered — look it up again
        } catch (ElementClickInterceptedException e) {
            // something is covering it: scroll it to the middle and retry once
            ((JavascriptExecutor) driver).executeScript(
                "arguments[0].scrollIntoView({block:'center'});",
                driver.findElement(locator));
            attempts++;
        }
    }
    throw new FrameworkException("Could not click " + locator + " after 3 attempts. URL="
            + driver.getCurrentUrl());
}
Interviewers often follow up with "isn't this hiding a problem?" The answer: "It absorbs a genuine race in a re-rendering SPA. It does not silently pass — it fails loudly after three attempts with the URL in the message. And I'd still prefer to fix the root cause by waiting for the re-render to finish."

Q235Write code to scroll an infinite-scroll page until a given item appears (or the page stops growing).▼
public WebElement scrollUntilFound(By locator, int maxScrolls) {
    JavascriptExecutor js = (JavascriptExecutor) driver;
    long previousHeight = -1;

    for (int i = 0; i < maxScrolls; i++) {
        List<WebElement> found = driver.findElements(locator);
        if (!found.isEmpty()) {
            js.executeScript("arguments[0].scrollIntoView({block:'center'});", found.get(0));
            return found.get(0);
        }

        long height = (Long) js.executeScript("return document.body.scrollHeight");
        if (height == previousHeight) break;               // nothing new loaded — stop
        previousHeight = height;

        js.executeScript("window.scrollTo(0, document.body.scrollHeight);");
        wait.until(d -> (Long) ((JavascriptExecutor) d)
                .executeScript("return document.body.scrollHeight") != height
                || !d.findElements(locator).isEmpty());
    }
    throw new NoSuchElementException("Not found after scrolling: " + locator);
}
Two things to say aloud: the maxScrolls guard (never write an unbounded loop in a test) and the height-unchanged break (detects the true end of the list instead of scrolling forever).

Q236Write code to switch to a browser window by its title, and back.▼
public String switchToWindowByTitle(String expectedTitle) {
    String original = driver.getWindowHandle();

    wait.until(d -> d.getWindowHandles().size() > 1);       // wait for the new window

    for (String handle : driver.getWindowHandles()) {
        driver.switchTo().window(handle);
        if (driver.getTitle().contains(expectedTitle)) {
            return original;                                // caller keeps it to switch back
        }
    }
    driver.switchTo().window(original);                     // nothing matched — restore state
    throw new NoSuchWindowException("No window with title containing: " + expectedTitle);
}

// usage

Q237Write a generic method that verifies a table column is sorted.▼
public enum SortOrder { ASC, DESC }

/**
 * @param parser converts the cell text into something Comparable
 *               (e.g. Double::parseDouble for prices, LocalDate::parse for dates)
 */
public <T extends Comparable<T>> void assertColumnSorted(
        By cellLocator, Function<String, T> parser, SortOrder order) {

    List<T> actual = driver.findElements(cellLocator).stream()
            .map(WebElement::getText)
            .map(String::trim)
            .filter(s -> !s.isEmpty())
            .map(parser)
            .toList();

    if (actual.size() < 2) throw new SkipException("Not enough rows to verify sorting");

    List<T> expected = new ArrayList<>(actual);
    expected.sort(order == SortOrder.ASC
            ? Comparator.naturalOrder() : Comparator.reverseOrder());

    Assert.assertEquals(actual, expected,
            "Column is not sorted " + order + ". Actual order was: " + actual);
}

// usage
assertColumnSorted(By.cssSelector("td.price"),
        s -> Double.parseDouble(s.replaceAll("[^0-9.]", "")), SortOrder.ASC);
assertColumnSorted(By.cssSelector("td.date"),
        s -> LocalDate.parse(s, DateTimeFormatter.ofPattern("dd/MM/yyyy")), SortOrder.DESC);
Generics + a parser function is exactly the kind of reusable design a 5-year candidate is expected to reach for, instead of writing verifyPriceSorted(), verifyDateSorted(), verifyNameSorted().

Q238Write an Excel reader wired into a TestNG DataProvider.▼
public final class ExcelReader {
    public static List<Map<String,String>> read(String path, String sheetName) {
        List<Map<String,String>> rows = new ArrayList<>();
        try (FileInputStream fis = new FileInputStream(path);
             Workbook wb = new XSSFWorkbook(fis)) {

            Sheet sheet = Optional.ofNullable(wb.getSheet(sheetName))
                    .orElseThrow(() -> new FrameworkException("No sheet: " + sheetName));
            Row header = sheet.getRow(0);
            DataFormatter fmt = new DataFormatter();      // reads any cell type as text

            for (int r = 1; r <= sheet.getLastRowNum(); r++) {
                Row row = sheet.getRow(r);
                if (row == null) continue;
                Map<String,String> map = new LinkedHashMap<>();
                for (int c = 0; c < header.getLastCellNum(); c++) {
                    map.put(fmt.formatCellValue(header.getCell(c)),
                            fmt.formatCellValue(row.getCell(c)));
                }
                if (map.values().stream().anyMatch(v -> !v.isBlank())) rows.add(map);
            }
        } catch (IOException e) {
            throw new FrameworkException("Failed reading " + path, e);
        }
        return rows;
    }
    private ExcelReader() { }
}

Q239Write a TestNG listener that screenshots on failure and logs to the report.▼
public class TestListener implements ITestListener {

    @Override public void onTestStart(ITestResult result) {
        ExtentManager.set(ExtentManager.report()
                .createTest(result.getMethod().getMethodName(),
                            result.getMethod().getDescription()));
        ExtentManager.test().assignCategory(result.getMethod().getGroups());
    }

    @Override public void onTestSuccess(ITestResult result) {
        ExtentManager.test().pass("Passed in "
                + (result.getEndMillis() - result.getStartMillis()) + " ms");
        ExtentManager.unload();
    }

    @Override public void onTestFailure(ITestResult result) {
        WebDriver driver = DriverFactory.get();
        if (driver != null) {
            String base64 = ((TakesScreenshot) driver).getScreenshotAs(OutputType.BASE64);
            ExtentManager.test().fail(result.getThrowable(),
                MediaEntityBuilder.createScreenCaptureFromBase64String(base64).build());
            ExtentManager.test().info("URL at failure: " + driver.getCurrentUrl());
            driver.manage().logs().get(LogType.BROWSER).getAll().stream()
                  .filter(e -> e.getLevel() == Level.SEVERE)
                  .forEach(e -> ExtentManager.test().warning("console: " + e.getMessage()));
        } else {
            ExtentManager.test().fail(result.getThrowable());
        }
        ExtentManager.unload();
    }

    @Override public void onTestSkipped(ITestResult result) {
        ExtentManager.test().skip(result.getThrowable());
        ExtentManager.unload();
    }

    @Override public void onFinish(ITestContext context) {
        ExtentManager.report().flush();
    }
}
The null check on the driver matters: if setup itself failed, there is no driver, and a listener that throws an NPE hides the original failure completely. That is a real bug I'd expect a senior candidate to anticipate.

Q240Write code that verifies every image on a page has meaningful alt text and actually loads.▼
@Test
public void allImagesHaveAltTextAndLoad() {
    JavascriptExecutor js = (JavascriptExecutor) driver;
    List<WebElement> images = driver.findElements(By.tagName("img"));
    Assert.assertFalse(images.isEmpty(), "No images found — is the page loaded?");

    SoftAssert soft = new SoftAssert();
    for (WebElement img : images) {
        String src = img.getAttribute("src");
        String alt = img.getAttribute("alt");

        // alt="" is VALID for decorative images; a missing attribute is not
        soft.assertNotNull(alt, "Missing alt attribute on image: " + src);

        // did the image actually render? naturalWidth is 0 for a broken image
        Long naturalWidth = (Long) js.executeScript(
                "return arguments[0].naturalWidth;", img);
        soft.assertTrue(naturalWidth != null && naturalWidth > 0,
                "Broken image (failed to load): " + src);
    }
    soft.assertAll();
}
naturalWidth === 0 is the standard way to detect a broken image — the <img> element exists and is "visible" to Selenium even when the file 404s, so isDisplayed() tells you nothing. Knowing that distinction is a strong signal.

Q241Write code to measure page load performance from a test.▼
public Map<String, Long> capturePageTimings() {
    JavascriptExecutor js = (JavascriptExecutor) driver;

    Long navigationStart = (Long) js.executeScript(
            "return window.performance.timing.navigationStart;");
    Long domContentLoaded = (Long) js.executeScript(
            "return window.performance.timing.domContentLoadedEventEnd;");
    Long loadComplete = (Long) js.executeScript(
            "return window.performance.timing.loadEventEnd;");
    Long responseEnd = (Long) js.executeScript(
            "return window.performance.timing.responseEnd;");

    return Map.of(
        "serverResponseMs", responseEnd - navigationStart,
        "domReadyMs",       domContentLoaded - navigationStart,
        "fullLoadMs",       loadComplete - navigationStart);
}

@Test
public void homePageLoadsWithinBudget() {
    driver.get(Config.get("base.url"));
    Map<String, Long> timings = capturePageTimings();
    logger.info("Page timings: {}", timings);
    Assert.assertTrue(timings.get("fullLoadMs") < 3000,
            "Home page took " + timings.get("fullLoadMs") + "ms, budget is 3000ms");
}

Playwright equivalent, plus modern Core Web Vitals:

const nav = JSON.parse(await page.evaluate(
  () => JSON.stringify(performance.getEntriesByType('navigation')[0])));
expect(nav.loadEventEnd).toBeLessThan(3000);

  new PerformanceObserver(list => {
    const entries = list.getEntries();
    resolve(entries[entries.length - 1].startTime);
  }).observe({ type: 'largest-contentful-paint', buffered: true });
}));
expect(lcp).toBeLessThan(2500);          // Google's "good" LCP threshold
Be honest about the limit: this is single-user front-end timing, not load testing. It catches a regression where someone ships a 4MB unoptimised hero image; it says nothing about behaviour at 500 concurrent users.

// fixtures.ts
import { test as base, APIRequestContext } from '@playwright/test';

type Order = { id: string; sku: string; total: number };

type Fixtures = {
  testOrder: Order;
  api: APIRequestContext;
};

export const test = base.extend<Fixtures>({
  api: async ({ playwright }, use) => {
    const ctx = await playwright.request.newContext({
      baseURL: process.env.API_URL,
      extraHTTPHeaders: { Authorization: `Bearer ${process.env.API_TOKEN}` },
    });
    await use(ctx);
    await ctx.dispose();
  },

  testOrder: async ({ api }, use, testInfo) => {
    // unique per test AND per worker, so parallel runs never collide
    const ref = `AUTOTEST-${testInfo.workerIndex}-${Date.now()}`;

    const res = await api.post('/api/v1/orders', {
      data: { reference: ref, sku: 'TSH-001', qty: 1 },
    });
    if (!res.ok()) throw new Error(`Order setup failed: ${res.status()} ${await res.text()}`);
    const order: Order = await res.json();

    await use(order);                              // ← the test body runs here

    // teardown runs even if the test failed
    await api.delete(`/api/v1/orders/${order.id}`).catch(() => { /* already gone */ });
  },
});

export { expect } from '@playwright/test';
Three things to call out: setup through the API not the UI (fast and stable), a unique reference including the worker index (parallel-safe), and teardown that tolerates already-deleted data so cleanup never masks the real failure.

Q246Write code that verifies the UI, the API and the database agree.▼
@Test
public void placedOrderIsConsistentAcrossUiApiAndDatabase() {
    // 1. UI — perform the business action
    String orderRef = checkoutPage.placeOrder();
    BigDecimal uiTotal = confirmationPage.getTotalAmount();

    // 2. API — the service agrees
    Response api = given().spec(requestSpec).get("/api/v1/orders/" + orderRef);
    api.then().statusCode(200);
    BigDecimal apiTotal = new BigDecimal(api.path("total").toString());

    // 3. DB — the data was actually persisted, with the audit trail
    OrderRow db = queryOrder(orderRef);

    SoftAssert soft = new SoftAssert();
    soft.assertEquals(apiTotal.compareTo(uiTotal), 0,
            "UI total " + uiTotal + " != API total " + apiTotal);
    soft.assertEquals(db.total.compareTo(uiTotal), 0,
            "UI total " + uiTotal + " != DB total " + db.total);
    soft.assertEquals(db.status, "CONFIRMED");
    soft.assertNotNull(db.createdAt, "Audit timestamp missing");
    soft.assertAll();
}

private OrderRow queryOrder(String ref) {
    String sql = "SELECT status, total_amount, created_at FROM orders WHERE order_ref = ?";
    try (Connection con = DriverManager.getConnection(
                Config.get("db.url"), Config.get("db.user"), Config.get("db.password"));
         PreparedStatement ps = con.prepareStatement(sql)) {
        ps.setString(1, ref);
        try (ResultSet rs = ps.executeQuery()) {
            if (!rs.next()) throw new AssertionError("No DB row for order " + ref);
            return new OrderRow(rs.getString("status"),
                                rs.getBigDecimal("total_amount"),
                                rs.getTimestamp("created_at"));
        }
    } catch (SQLException e) {
        throw new FrameworkException("DB verification failed for " + ref, e);
    }
}
Note BigDecimal.compareTo(…) == 0 rather than equals: new BigDecimal("1499.0").equals(new BigDecimal("1499.00")) is false because equals compares scale. That is a real money bug and a superb detail to mention unprompted.

Q247Write a test-data factory that generates unique, parallel-safe data.▼
public final class TestDataFactory {
    private static final Faker FAKER = new Faker(new Locale("en-IND"));
    private static final AtomicInteger COUNTER = new AtomicInteger();

    /** Unique across parallel threads AND across re-runs on the same machine. */
    public static String uniqueEmail() {
        return String.format("qa_%d_%d_%d@test.example.com",
                System.currentTimeMillis(),
                Thread.currentThread().getId(),
                COUNTER.incrementAndGet());
    }

    public static User newUser() { return newUser(u -> {}); }

    /** Builder-with-overrides: sensible defaults, override only what the test cares about. */
    public static User newUser(Consumer<User.Builder> overrides) {
        User.Builder b = User.builder()
                .email(uniqueEmail())
                .name(FAKER.name().fullName())
                .phone("9" + FAKER.number().digits(9))
                .role("USER")
                .active(true);
        overrides.accept(b);
        return b.build();
    }

    /** Dates must be RELATIVE — a hardcoded date expires and the test fails next year. */
    public static LocalDate futureBookingDate() { return LocalDate.now().plusDays(7); }
    public static String futureCardExpiry() {
        return LocalDate.now().plusYears(2).format(DateTimeFormatter.ofPattern("MM/yy"));
    }

    private TestDataFactory() { }
}

// usage — the test states only what matters to it
User admin = TestDataFactory.newUser(u -> u.role("ADMIN"));
User locked = TestDataFactory.newUser(u -> u.active(false));
The "defaults plus overrides" pattern is worth naming explicitly: the test declares only the attribute under test, so when a new mandatory field is added you change one factory instead of 200 tests.

Q248Write a utility that masks sensitive data before it reaches logs or reports.▼
public final class Mask {
    private static final Pattern CARD  = Pattern.compile("\\b(?:\\d[ -]*?){13,19}\\b");
    private static final Pattern EMAIL = Pattern.compile("([\\w.+-]{1,3})[\\w.+-]*@([\\w.-]+)");
    private static final Pattern PHONE = Pattern.compile("\\b(\\d{2})\\d{6}(\\d{2})\\b");
    private static final List<String> SECRET_KEYS =
            List.of("password", "token", "authorization", "secret", "cvv", "otp", "apiKey");

    public static String text(String input) {
        if (input == null) return null;
        String out = CARD.matcher(input).replaceAll(m -> keepLast4(m.group()));
        out = EMAIL.matcher(out).replaceAll("$1***@$2");
        out = PHONE.matcher(out).replaceAll("$1******$2");
        return out;
    }

    /** Masks values of known-sensitive keys in a JSON body before logging it. */
    public static String json(String body) {
        String out = body;
        for (String key : SECRET_KEYS) {
            out = out.replaceAll("(?i)(\"" + key + "\"\\s*:\\s*\")[^\"]*(\")", "$1***$2");
        }
        return out;
    }

    private static String keepLast4(String digits) {
        String clean = digits.replaceAll("\\D", "");
        return clean.length() < 4 ? "****"
                : "*".repeat(clean.length() - 4) + clean.substring(clean.length() - 4);
    }
    private Mask() { }
}

// usage
logger.info("Request: {}", Mask.json(payload));
ExtentManager.test().info("Paying with " + Mask.text(cardNumber));   // **** **** **** 1111

Q249Write a driver factory that supports local, headless, remote grid and mobile.▼
public final class DriverFactory {
    private static final ThreadLocal<WebDriver> TL = new ThreadLocal<>();

    public static void init() {
        String target  = Config.get("run.target");     // local | grid | mobile
        String browser = Config.get("browser");
        boolean headless = Config.getBool("headless");

        WebDriver driver = switch (target.toLowerCase()) {
            case "grid"   -> remote(browser, headless);
            case "mobile" -> mobile();
            default       -> local(browser, headless);
        };
        driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(45));
        if (!"mobile".equalsIgnoreCase(target)) driver.manage().window().maximize();
        TL.set(driver);
    }

    private static WebDriver local(String browser, boolean headless) {
        return switch (browser.toLowerCase()) {
            case "firefox" -> new FirefoxDriver(firefoxOptions(headless));
            case "edge"    -> new EdgeDriver(new EdgeOptions());
            case "chrome"  -> new ChromeDriver(chromeOptions(headless));
            default -> throw new IllegalArgumentException("Unsupported browser: " + browser);
        };
    }

    private static WebDriver remote(String browser, boolean headless) {
        try {
            AbstractDriverOptions<?> options = "firefox".equalsIgnoreCase(browser)
                    ? firefoxOptions(headless) : chromeOptions(headless);
            RemoteWebDriver driver = new RemoteWebDriver(
                    new URL(Config.get("grid.url")), options);
            driver.setFileDetector(new LocalFileDetector());   // enables file upload on nodes
            return driver;
        } catch (MalformedURLException e) {
            throw new FrameworkException("Bad grid URL: " + Config.get("grid.url"), e);
        }
    }

    private static ChromeOptions chromeOptions(boolean headless) {
        ChromeOptions o = new ChromeOptions();
        if (headless) o.addArguments("--headless=new", "--window-size=1920,1080");
        o.addArguments("--no-sandbox", "--disable-dev-shm-usage", "--disable-notifications");
        o.setExperimentalOption("prefs",
                Map.of("profile.default_content_setting_values.notifications", 2));
        return o;
    }

    public static WebDriver get() {
        WebDriver d = TL.get();
        if (d == null) throw new IllegalStateException(
                "Driver not initialised on thread " + Thread.currentThread().getName());
        return d;
    }

    public static void quit() {
        WebDriver d = TL.get();
        if (d != null) {
            try { d.quit(); } finally { TL.remove(); }   // remove() even if quit() throws
        }
    }
    private DriverFactory() { }
}
The try { quit(); } finally { TL.remove(); } detail matters: if quit() throws because the browser already crashed, a naive implementation leaks the ThreadLocal and the next test on that pooled thread inherits a dead driver.

Q250Live exercise: "Automate this flow on a site you've never seen." How do you approach it?▼

Many companies now do this instead of theory questions — they open a demo site (saucedemo, the-internet, automationexercise) and ask you to automate a flow while sharing your screen. They are watching your process, not your typing speed.

  1. Clarify first. "Should I write this as a full framework or a single script? Do you want me to prioritise structure or coverage in the time we have?" This alone puts you ahead of most candidates.
  2. Explore the app for two minutes before writing anything. Walk the flow manually, open DevTools, and look at what locators exist. Say what you see: "there are no test ids, but the ids look stable, so I'll use those."
  3. Write the test first, top-down, as if the page objects already existed: 
    @Test
public void userCanBuyAProduct() {
    loginPage.loginAs(user, pass);
    productsPage.addToCart("Sauce Labs Backpack");
    cartPage.checkout();
    checkoutPage.fillDetails("Ravi", "Kumar", "560001");
    Assert.assertEquals(confirmationPage.getMessage(), "Thank you for your order!");
}
    Then implement downwards. It shows design thinking and gives you a working skeleton even if you run out of time.
  4. Narrate the trade-offs. "I'm using an explicit wait here rather than an implicit one because…" — the commentary is most of your score.
  5. Add one negative test if time allows. Almost every candidate automates only the happy path; adding "login with a locked-out user" shows a tester's instinct rather than a coder's.
  6. Finish with what you'd do next: "with more time I'd externalise the test data, add the driver factory for cross-browser, and wire this into CI with a screenshot listener." That turns an unfinished exercise into a demonstration of judgement.
Practise on saucedemo.com and the-internet.herokuapp.com until you can produce a clean POM-structured login-to-checkout test in 20 minutes from a blank file, talking the whole time. That single rehearsal is worth more than another 50 questions of theory.
