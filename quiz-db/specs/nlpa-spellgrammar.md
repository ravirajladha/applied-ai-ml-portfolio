**Ladder:** NLP Applications (AIMLCZG519) › Session 2 Spell check and grammar check   ·   **Prerequisites:** nlpa-overview (pipeline, approaches), basic probability (Bayes' rule, conditional probability), precision/recall
**Why it matters for AI/ML:** Spell and grammar checking is the course's first application and a preprocessing step for search, RAG and agents ("wether in pune" -> "weather in Pune", "delte file" before a tool call). It teaches the core ideas reused all course long: edit distance and candidate generation, the noisy channel (a prior times a likelihood), n-gram language models with smoothing, sequence decoding over a lattice, and precision-weighted evaluation. Every midsem opens with a 6-7 mark spellcheck question: classify the errors, run the noisy channel on a given table, argue precision vs recall for a domain, build a trie or pick edit distance vs Soundex.

## Must-know facts
- Error types (course): non-word ('recieve'), real-word ('their' vs 'there', 'form' for 'from'), syntactic ('She go to school'), semantic ('colorless green ideas'), punctuation (missing commas, apostrophes).
- Hybrid tiers: Tier 1 dictionary/regex (fast, typos, custom lists) -> Tier 2 statistical n-grams (local context) -> Tier 3 neural transformer (full semantic correction, rewrites).
- Levenshtein: d(i,j) = min(d(i-1,j)+1 delete, d(i,j-1)+1 insert, d(i-1,j-1)+cost) with cost 0 if letters match; the course uses substitution cost 1 (J&M's 'intention -> execution' is 5 with cost 1, 8 with substitution cost 2). Damerau-Levenshtein adds transposition of adjacent letters as one edit. O(mn) time.
- Trie: O(k) lookup for a k-letter word, prefix search for autocomplete. Soundex: keep first letter, map consonants (BFPV 1, CGJKQSXZ 2, DT 3, L 4, MN 5, R 6), drop vowels, pad/truncate to 4 (night N230, Smith = Smythe = S530). BK-tree: metric tree keyed by edit distance; at a node at distance d from the query, only explore children with edge labels in [d-k, d+k] (triangle inequality). SymSpell: precompute deletion variants of dictionary words and the query (symmetric delete): very fast, more memory.
- ~80% of typos are within edit distance 1, almost all within 2 (Damerau 1964). Also allow space/hyphen insertion (thisidea -> this idea, inlaw -> in-law).
- Noisy channel: w^ = argmax_w P(w given x) = argmax_w P(x given w) P(w) / P(x) = argmax_w P(x given w) P(w). P(w) = language model (prior, fluency); P(x given w) = channel/error model (likelihood, fidelity).
- acress: candidates actress, cress, caress, access, across, acres; actress 2.7e-9 vs across 2.8e-9: the channel alone favours actress, the prior alone favours across/access; context decides.
- Confusion-matrix channel (Kernighan et al.): del[w(i-1), w(i)] / count[w(i-1) w(i)]; ins[w(i-1), x(i)] / count[w(i-1)]; sub[x(i), w(i)] / count[w(i)]; trans[w(i), w(i+1)] / count[w(i) w(i+1)]. Add-1: (sub[x,w] + 1) / (count[w] + |A|).
- Bigram LM: P(w1..wn) = P(w1) P(w2 given w1) ... ; MLE P(wk given wk-1) = C(wk-1, wk) / C(wk-1). Add-1: (C + 1) / (C(wk-1) + V). Interpolation: lambda Puni + (1 - lambda) Pbi. 'versatile actress whose' = .000021 x .0010 = 210e-10 vs 'versatile across whose' = 1e-10.
- Real-word correction: every word gets a candidate set that includes itself; choose the sequence W maximising P(W) (channel at nodes, bigram LM on edges). 'two of thew': 4 x 3 x 4 = 48 paths; with one error per sentence 3 + 2 + 3 = 8 changed sentences plus the original.
- Grammar checking: tokenization -> POS tagging -> parsing -> error detection -> suggestion; rule-based (LanguageTool, thousands of rules), constituency and dependency parsing, statistical (After the Deadline), neural GEC (T5, BART, GECToR), LLM prompting.
- GECToR: 'Tag, not rewrite'; encoder-only (BERT/RoBERTa) predicts one edit tag per token ($KEEP, $DELETE, $APPEND_x, $REPLACE_x, $TRANSFORM_VERB_VB_VBD...), iterates up to ~5 passes, trained in three stages (synthetic -> errorful Lang-8 -> gold BEA-2019); 10-100x faster than seq2seq, cannot hallucinate new content, confidence threshold tunes precision.
- Evaluation: P = correct edits / proposed edits; R = correct edits / reference edits; F0.5 = 1.25PR / (0.25P + R) (precision-weighted; CoNLL-2014, BEA-2019); ERRANT types edits (SPELL, MORPH, R:VERB:TENSE...); JFLEG uses GLEU.

## Common traps (each one must have at least one question)
- Dictionary check catches real-word errors -> 'form' for 'from' passes; real-word errors need context.
- Using substitution cost 2 when the course says 1 (or vice versa) -> state the cost; intention/execution is 5 vs 8.
- Forgetting the transposition edit -> 'teh' is 2 in Levenshtein, 1 in Damerau-Levenshtein.
- Ranking by P(w) alone (most frequent word wins) or by P(x given w) alone (closest edit wins).
- Keeping P(x) in the argmax -> it is the same for every candidate.
- Multiplying many small probabilities -> underflow; use log probabilities.
- Unseen error types get P = 0 -> add-1 smoothing of the confusion matrix (qa, aq).
- Unsmoothed bigram -> one unseen bigram zeroes the whole sentence.
- Not including the typed word as its own candidate -> real-word systems 'correct' correct words.
- Soundex for typing errors or words whose first letter changes (fone vs phone: F500 vs P500).
- F0.5 'weights recall more' -> it weights precision more (beta < 1).
- The slides' generic F-score line P*R/(P+R) omits the factor 2 -> F1 = 2PR/(P+R).
- LLM correctors 'improve' already-correct text or change meaning (member -> follower) -> minimal-edit prompting, meaning checks.

## Interview angle
1. **"Design a spell checker for e-commerce search."** Tier 1 dictionary + brand/product list (samsumg -> samsung), candidates within edit distance 2 via SymSpell/BK-tree, noisy-channel ranking with query-log priors, context from bigrams; prefer precision (wrong corrections hide products), offer 'did you mean'.
2. **"Walk me through the noisy channel."** x observed, candidates w from edit distance, score P(x given w) from confusion matrices times P(w) from a LM, argmax; P(x) drops out; add context with a bigram LM.
3. **"How do you correct real-word errors?"** Candidate set per word including itself, lattice of sentences, LM + channel scoring, usually one error per sentence to limit the search, or a contextual classifier / BERT.
4. **"GECToR vs a seq2seq GEC model?"** Tagging is faster, controllable and cannot hallucinate; seq2seq/LLMs rewrite more fluently but over-edit and may change meaning.
5. **"Why F0.5?"** A wrong correction introduces an error into correct text; precision matters more than recall for user trust.
