## Must-know facts
- QA answers one question (transactional, stateless); conversational AI holds a multi-turn, stateful, goal-oriented dialogue. For simple repetitive questions, conversational AI is overkill: a QA system is cheaper, faster and safer.
- Factoid questions have short fact answers (who / where / how many); complex (narrative) questions need explanation and synthesis. Commercial systems are mainly factoid.
- QA evolution: IR-based -> knowledge-based -> hybrid (IR + knowledge) -> deep learning -> transformers -> RAG.
- IR-based factoid QA has three stages: question processing (detect question type, answer type, focus, relations; formulate the query), passage retrieval (retrieve documents, split into passages, rerank), answer processing (extract and rank candidates).
- Knowledge-based QA (Siri): build a semantic representation (times, dates, locations, entities, quantities) and map it to structured sources (geospatial DBs, ontologies like DBpedia, WordNet, Yago, reservation services). Hybrid (IBM Watson): shallow semantics, IR candidate generation augmented with ontologies, score candidates with richer knowledge (geospatial, temporal, taxonomic).
- Extractive QA: given question + context, output the start and end of the answer span (a "digital highlighter"; BERT on SQuAD). Low hallucination; cannot synthesise; fails when the answer is spread across the document or the question has several sub-questions. Generative QA (GPT, T5): "expert answering from memory"; flexible, but hallucinates and is stale. RAG: open-book exam.
- Comparison (course): IR returns document snippets (low cost, low hallucination); generative is high-risk; RAG medium-low risk, medium-high cost; agentic AI is best on complex questions but high cost.
- Metrics: EM = 1 if normalised prediction == normalised gold; token F1 over shared tokens; P@k = relevant in top k / k; R@k = relevant in top k / total relevant; MRR = mean of 1/rank of first correct answer (0 if none); Hits@k = queries with a correct answer in top k / queries; MAP = mean of average precision; nDCG@k = DCG@k / IDCG@k with DCG = Σ rel_i / log2(i + 1); ROUGE-L = F of LCS precision and recall.
- Dialogue acts (course): constatives (answering, claiming, confirming, denying, stating), directives (asking, requesting, ordering, advising, inviting), commissives (promising, planning, vowing, betting), acknowledgments (apologising, greeting, thanking).
- Grounding = acknowledging that the hearer understood. Adjacency pairs: question -> answer, proposal -> acceptance/rejection, compliment -> downplayer. Clarification subdialogues sit between a request and its response. Inference: "I need to be there for a meeting from the 12th to the 15th" answers "what day?" only implicitly. Coreference: "send her an email" -> "my mom".
- Chatbot history: ELIZA (1966, pattern-action rules), statistical models (1990s-2000s), seq2seq (2010s), transformers / LLMs / agentic AI (2020+). Architectures: rule-based; corpus-based (IR, encoder-decoder, transformers / LLM, agentic).
- IR-based chatbots: (1) find the most similar turn t to the user's turn q (tf-idf) and return the response to t; (2) return the most similar turn itself.
- Components of conversational AI: NLU (intent classification, slot filling, NER, semantic parsing, coreference, sentiment), dialogue management (state tracking, rule-based or neural policy, context, clarification), NLG (templates, neural generation, persona and tone).
- Frame-based (GUS-style, J&M ch. 15): a frame is a set of slots with values; the system asks questions to fill required slots and then acts. Slot filling is sequence labelling with BIO tags.
- Component approaches (course table): rule-based (regex NLU, templates, flowcharts), statistical (SVM / CRF / HMM NLU, POMDP policies), deep learning (BiLSTM-CRF slot tagging, seq2seq NLG, policy networks), LLM-based (implicit intents/slots via prompts, free-form NLG, LLM predicts next action), agentic (structured JSON intents/slots for tools, Thought -> Action -> Observation -> Response loops, memory).
- Evaluation: slot error rate = (inserted + deleted + substituted slots) / reference slots, per sentence; intent accuracy; state-tracking accuracy; task success (end-to-end: was the right meeting booked?). Conversational metrics: turn-level coherence, task success rate, CSAT, dialogue act accuracy. Design: user-centred (study users and task, iterate).
- Ethics: Tay (2016) was taken offline after 16 hours for learning abuse from users; dialogue datasets contain hate speech and bias; agents often given female names; privacy of recorded sensitive data (noticed since Weizenbaum).
- GenAI / agentic: LLM + RAG for grounding; tools / function calling (APIs, DB lookup, calculators, MCP); memory (short-term in-context, long-term vector store, episodic, semantic, session persistence); multi-agent orchestration; ReAct; guardrails and handoff to a human with full history; hybrid LLM + dialogue manager + rules / APIs for enterprise.

## Common traps (each one must have at least one question)
- Conversational AI for a store-hours FAQ -> overkill; a QA / FAQ system is cheaper, faster and safer.
- MRR counting every correct answer -> only the first correct one, and 1/rank; a miss is 0, not skipped.
- Hits@3 equal for two systems read as "equally good" -> MRR and Hits@1 separate them.
- nDCG IDCG built from the retrieved list -> it uses the best possible ordering of the corpus's relevance grades.
- EM = 0 read as "completely wrong" -> "Paris, France" vs "Paris" is partly right; F1 shows it.
- SER denominator = system slots -> it is reference slots; insertions count as errors.
- A deleted slot ignored because the system "did not get it wrong" -> deletion is an error.
- Labelling "What time would you prefer?" as constative -> it is a directive (asks the user to act).
- Labelling a system's "I've booked you" as commissive -> it reports a completed action (constative); commissive commits to a future action.
- Extractive QA for a question whose answer is spread over several paragraphs -> start/end span cannot cover it.
- Generative QA (no retrieval) for private policy questions -> hallucination, stale, no citations.
- Open-domain LLM chatbot for a regulated banking or healthcare task -> needs a goal-oriented (task) architecture with retrieval, rules and escalation.
- Sentiment wired into coreference resolution -> it belongs in NLU per turn, tracked in DST, acted on by the dialogue manager.
- Long-term memory = the context window -> the context window is short-term; long-term memory is an external store.

## Interview angle
1. **"Extractive vs generative vs RAG QA?"** Extractive highlights a span (precise, can't synthesise); generative answers from memory (fluent, hallucinates, stale); RAG generates from retrieved documents (grounded, fresh, citable).
2. **"Walk me through a task-oriented dialogue system."** NLU (intent + slots) -> dialogue state tracker (intent, filled slots, history) -> policy (ask for a missing slot, confirm, call an API, hand off) -> NLG; evaluate with SER, intent accuracy, state-tracking accuracy and task success.
3. **"How would you build a banking support bot with an LLM?"** Goal-oriented core with explicit state and business rules for regulated actions; LLM for NLU and NLG; RAG over policy docs; tools for account APIs; guardrails, sentiment-aware escalation to a human with full history; measure task success, SER, CSAT, hallucination rate.
4. **"MRR vs Hits@k vs nDCG?"** MRR rewards putting the first correct answer high; Hits@k only checks presence in the top k; nDCG handles graded relevance and position.
