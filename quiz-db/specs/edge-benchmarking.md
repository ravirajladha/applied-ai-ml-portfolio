## Must-know facts
- Latency = time per inference (ms); throughput = inferences per second; power = W; energy per inference = average power × latency (W × ms = mJ); memory = Flash/storage for the model plus peak RAM at run time.
- With batch 1 and one stream, throughput ≈ 1000 / latency_ms; batching or parallel streams raise throughput but each request can wait longer. 1 / throughput is not single-request latency.
- p50 is the median; p95 means 95% of inferences finished at or below that time. Tails (p95, p99) matter for SLAs and control loops; the mean hides them. Jitter (spread, e.g. p99 − p50) matters for real-time control. The bank uses NumPy's default linear-interpolation percentile unless a question says nearest-rank.
- Method: discard warm-up runs (first inference pays for allocation, delegate set-up, caches and JIT), repeat many runs, fix threads, batch size, input size and power mode, watch temperature (thermal throttling lowers clocks during long runs), and state whether timing is model-only or end-to-end (capture + preprocessing + inference + postprocessing).
- TFLite benchmark tool (`benchmark_model`): `--graph`, `--num_threads`, `--warmup_runs`, `--num_runs`, `--use_gpu`, `--use_xnnpack`, `--enable_op_profiling`; it prints init time, first-inference time, warm-up average and steady-state inference average (with min/max/std over runs) in microseconds, plus memory footprint. Per-op profiling shows which operators take the time.
- MLPerf Tiny (MLCommons, with EEMBC's EnergyRunner for energy): four tasks: keyword spotting (Speech Commands, DS-CNN), visual wake words (person / no person, MobileNetV1 0.25x), image classification (CIFAR-10, ResNet-8) and anomaly detection (ToyADMOS machine sounds, FC autoencoder). It reports latency and, optionally, energy per inference; the closed division fixes the reference model, the open division allows changes.
- MLPerf Inference (edge) scenarios: single-stream (one query at a time, metric = 90th-percentile latency), multi-stream, offline (throughput, samples/s).
- Energy KPIs: energy per inference (mJ or µJ), inferences per joule (= 1 / energy per inference in J), TOPS/W (a peak hardware number, not a model measurement), average power under a duty cycle = P_active × d + P_sleep × (1 − d), battery life = battery energy / average power.
- Pareto dominance (accuracy up, latency down): A dominates C if A is at least as good on both and strictly better on at least one. The frontier is the set of non-dominated models. Never select a dominated model: another model is at least as good on everything and better on something.
- SLA selection: first drop models that violate the SLA (strictly below means a model exactly at the limit fails), then pick from the remaining frontier models, usually the most accurate one; check remaining constraints (size, power).
- Reports: latency histograms (bimodal = two behaviours, e.g. cache miss or CPU fallback), box plots (median, IQR, outliers), op-profile tables (% of time per op), latency vs batch curves (throughput rises, latency rises), accuracy-latency scatter with the frontier drawn.
- TinyML = ML on microcontrollers in the mW range and below, always-on sensing (keyword spotting, vibration, gesture). TFLite Micro uses a fixed tensor arena, no OS or dynamic allocation; models are often tens to hundreds of KB.
- Edge GenAI: small LLMs (about 1-4B parameters) quantized to 4-bit (~0.5 byte/param, a 3B model ≈ 1.5 GB) run on phones and Jetsons with runtimes such as llama.cpp, MLC LLM and ExecuTorch. Decode is memory-bandwidth-bound: tokens/s ≲ memory bandwidth ÷ model bytes. Compressed diffusion cuts the number of denoising steps (step distillation) and the UNet size so images generate on-device in seconds.
- Multimodal fusion: early (combine raw data/features), intermediate (fuse learned features), late (combine per-modality decisions). Late fusion degrades gracefully when one sensor fails.
- Swarm edge AI: many autonomous devices (drones, vehicles, robots) share local observations and decide collectively without a central controller; it trades communication and consensus cost for robustness.
- Federated analytics computes aggregate statistics across devices without collecting raw data (no model training). Split learning cuts a model at a cut layer: the device runs the first layers and sends the cut-layer activations ("smashed data"); the server runs the rest and sends gradients back. Raw data stays local, but activations can leak information.
- Green AI (Schwartz et al. 2020): report efficiency (energy, FLOPs, carbon) alongside accuracy. Carbon = energy (kWh) × grid intensity (India ~0.7 kg CO2/kWh, convention used here). Energy-aware scheduling runs heavy work when energy is cheap/clean (solar hours, charging), uses DVFS and race-to-idle.

## Common traps (each one must have at least one question)
- Including the first (warm-up) inference in the average -> inflated latency; discard warm-up runs.
- Reporting the mean when the SLA is on p95/p99 -> the mean hides the tail.
- Treating the maximum of 20 runs as p99 -> too few samples to estimate a 1% tail.
- Throughput gains from batching or parallel streams read as lower latency -> each request still takes as long (or longer, with batching).
- "A dominates C" claimed when A is better on one metric and worse on the other -> neither dominates.
- Equal on both metrics -> neither dominates (strictly better on at least one is required).
- A model exactly at the limit under "strictly below 10 ms" -> it fails the SLA.
- Picking the most accurate model overall when it violates the SLA.
- Selecting a dominated model "because it meets every constraint" -> a frontier model is at least as good on all metrics.
- Comparing chips by TOPS or TOPS/W -> peak numbers; measured inferences per joule on your model is what counts.
- Low power assumed to mean low energy -> energy = power × time; a slower, low-power chip can use more energy per inference.
- Benchmark on a cool board for 10 seconds -> sustained runs throttle; measure in steady thermal state.
- Model-only latency quoted as the user-facing latency -> preprocessing and capture can dominate end-to-end time.
- Split learning assumed fully private -> smashed activations can leak input information.
- Federated analytics confused with federated learning -> analytics computes statistics, no model is trained.
- "LLM tokens/s scales with TOPS" on a phone -> decode is memory-bandwidth-bound.

## Interview angle
1. **"How do you benchmark a model on a Raspberry Pi?"** Fix threads, power mode and input; run benchmark_model with warm-up runs discarded and many timed runs; report p50/p95 and throughput, peak memory and energy (power meter × latency), end-to-end as well as model-only; repeat after the board reaches thermal steady state.
2. **"Four models, accuracy and p95 latency, SLA strictly below X ms. Which do you pick?"** Do the dominance checks, list the frontier, remove SLA violators (watch the boundary), pick the most accurate remaining frontier model, and say why dominated models are never chosen.
3. **"Chip A has 2x the TOPS/W of chip B. Is it more efficient for your model?"** Not necessarily: TOPS/W is peak; utilisation, memory traffic and op support decide real inferences per joule. Measure.
4. **"What is MLPerf Tiny?"** An MLCommons benchmark suite for microcontroller-class ML: keyword spotting, visual wake words, CIFAR-10 image classification and anomaly detection, with latency and energy measurement through EEMBC's EnergyRunner.
5. **"Split learning vs federated learning?"** FL trains full local models and sends updates; split learning splits one model at a cut layer and sends activations and gradients each step, which suits tiny devices but needs constant connectivity and leaks some information through activations.
