# Information Extraction (S13-S14): coverage spec

**Ladder:** NLP Applications (AIMLCZG519) › Information Extraction, Sessions 13-14   ·   **Prerequisites:** nlp-tokens (tokens, subwords), basic probability (conditional probability, argmax), precision/recall/F1
**Why it matters for AI/ML:** Information extraction turns free text (news, contracts, clinical notes) into database rows: entities, relation triples, event templates and normalised dates. It is the backbone of knowledge-graph construction, compliance monitoring and many "LLM returns JSON" features. The end-sem papers give a 7-mark IE question every time: NER P/R/F1 under exact match, relation triples, an event template with its trigger, temporal-expression classes, BIO tagging and a bootstrapping step.

## Must-know facts
- IE identifies specific pieces of information in unstructured or semi-structured text and turns them into a structured database or template. Course formula: IE = segmentation + classification + association.
- Course pipeline: NER and shallow parsing -> reference resolution -> relation detection and classification -> event detection and classification -> template filling.
- NE problems: variation (Manmohan Singh / Manmohan / Dr. Manmohan Singh) and type ambiguity (1945 date vs time, Washington location vs person, May person vs month, Tata person vs organisation); grey areas are often caused by metonymy.
- BIO (IOB): B-X starts an entity of type X, I-X continues it, O is outside. Every mention starts with B-. BIOES adds E- (end) and S- (single-token entity).
- Rule-based NER: hand rules and regexes ("Dr." + capitalised word -> PERSON, DD/MM/YYYY -> DATE). No training data, interpretable, high precision, low recall, costly to maintain.
- HMM: generative, P(tags, words) = Π P(t_i | t_{i-1}) P(w_i | t_i). Viterbi: v_t(j) = max_i v_{t-1}(i) · a_ij · b_j(o_t), then backtrace. MEMM: discriminative per-token, greedy or Viterbi inference, suffers label bias. CRF: one globally normalised score over the whole tag sequence with arbitrary overlapping features.
- BiLSTM-CRF: embeddings -> BiLSTM (context both ways) -> CRF layer that learns tag transitions (e.g. I-PER cannot follow B-ORG). Transformers (BERT) label each token; with subwords, usually only the first subword's label is scored.
- LLM NER: zero/few-shot, no retraining; but hallucination, higher inference cost, less consistent than fine-tuned models on benchmarks. RAG NER adds a domain knowledge base; agentic workflows chain NER, KG and validation agents.
- NER is scored at the entity (span) level, not per token. TP = span and type match a gold entity; FP = predicted entity with no match; FN = gold entity missed. P = TP/(TP+FP), R = TP/(TP+FN), F1 = 2PR/(P+R).
- Under exact match (CoNLL) a partial span or a wrong type is BOTH an FP (the prediction) and an FN (the gold entity). MUC / SemEval relaxed schemes give partial credit for overlap. Micro-F1 pools all entities; macro-F1 averages per-type F1.
- Relation triple: Relation(Arg1, Arg2), e.g. Founding-year(IBM, 1911). ACE types: Physical-Located (PER-GPE), Part-Whole-Subsidiary (ORG-ORG), Person-Social-Family (PER-PER), Org-AFF-Founder (PER-ORG). UMLS has 134 entity types and 54 relations.
- Hearst (1992) IS-A patterns: "Y such as X", "such Y as X", "X or other Y", "X and other Y", "Y including X", "Y, especially X". Hand patterns: high precision, low recall, a lot of work per relation.
- Supervised RE: find all entity pairs (usually same sentence) -> decide if related -> if yes classify the relation. The filter step speeds training by removing most pairs and allows separate feature sets.
- Bootstrapping: seed tuple -> find sentences containing it -> generalise patterns -> find new tuples -> iterate (Mark Twain / Elmira; DIPRE for author-book; Snowball adds NE-type constraints and pattern confidence). Distant supervision (Mintz 2009): use a large KB as a huge seed set, label every sentence that mentions both entities, train a supervised classifier: cheap but noisy.
- Semi-/unsupervised RE has no gold set: estimate precision on a random sample (and precision at top-N); recall cannot be measured.
- Event extraction finds who did what to whom, where and when: a trigger word plus role-labelled arguments filling a template. Relation extraction links two entities; event extraction links a trigger to one or more participants plus time and place.
- Temporal expressions: absolute (maps directly to a calendar date), relative (needs a reference point, e.g. next Monday), duration (a span such as six weeks). Recognition finds the start and end of each span (rule cascades of automata, or IOB sequence labelling with TIMEX3). Normalisation maps them to ISO values (TIMEX3 value="2026-03-09", duration "P6W"), anchoring relative expressions to the document creation time.

## Common traps (each one must have at least one question)
- Scoring NER per token -> the course scores entity spans; one boundary error fails the whole entity.
- Counting a partial span ("900" for "900 crore") as a TP or as only an FP -> under exact match it is one FP and one FN.
- Counting a wrong-type entity only once -> FP for the prediction and FN for the gold.
- Forgetting a repeated mention (2nd "FinEdge Capital") is a separate gold entity -> missed = FN.
- Starting an entity with I- or putting "the" inside an ORG span -> every mention begins with B-, determiners stay O.
- Greedy left-to-right tagging assumed to equal Viterbi -> greedy can lock in a locally best tag that loses globally.
- HMM vs CRF confused -> HMM is generative with independence assumptions; CRF is discriminative and globally normalised.
- Using BERT's subword labels directly as word labels -> align labels to the first subword, ignore the rest (-100).
- "Hand-written patterns give high recall" -> they give high precision, low recall.
- Distant supervision assumed clean -> a sentence mentioning both entities may not express the relation.
- Bootstrapping run without NE constraints or confidence -> semantic drift pulls in wrong tuples.
- Computing recall for Open IE / bootstrapped output -> no gold set; only sampled precision.
- Event extraction treated as NER -> it is about role relationships ("IBM purchased Microsoft" vs "IBM was purchased by Microsoft" have the same entities, opposite roles).
- "within six months" or "next Monday" classed as absolute -> relative (anchored to a reference time); "six weeks" is a duration.
- LLM triples trusted blindly -> hallucinated triples need validation and schema-constrained decoding.

## Interview angle
1. **"How do you evaluate an NER system?"** Entity-level P/R/F1 on held-out annotated data (CoNLL-2003); exact match needs span and type; partial matches and wrong types count as FP + FN; report micro-F1 overall and per-type F1 (macro) to see weak classes.
2. **"Why a CRF on top of a BiLSTM or BERT?"** Token-wise softmax picks each tag independently and can output I-PER after O. The CRF scores whole tag sequences with learned transitions, and Viterbi finds the best valid sequence.
3. **"No labelled data for a new relation, millions of documents and a KB: what do you do?"** Distant supervision from the KB (or bootstrapping from seeds), NE-typed patterns, a confidence threshold, then manually check precision on a random sample; LLM extraction with schema-constrained JSON is the modern alternative, but validate triples.
4. **"Pipeline or joint model?"** Pipelines are modular but propagate errors (a missed entity cannot become a relation argument); joint models (OneIE) share information across entities, relations and events and decode a global graph.
5. **"How would you turn 'by March 2026' and 'next Monday' into database dates?"** Recognise the spans, classify them, normalise to ISO values with TIMEX3, anchoring relative expressions to the document date.
