# Machine Translation (S10-S12): coverage spec

**Ladder:** NLP Applications (AIMLCZG519) › Sessions 10-12 Machine Translation   ·   **Prerequisites:** nlpa-spellgrammar (noisy channel, n-gram LMs), tf-attention (attention, encoder-decoder), llmc-eval (BLEU basics)
**Why it matters for AI/ML:** Translation is the task that produced most of modern NLP: the noisy channel and EM alignment (IBM models), attention (Bahdanau, as soft alignment), the Transformer and subword vocabularies were all invented for MT. The module walks the history RBMT -> SMT -> NMT -> Transformer -> LLM MT, teaches how to score a system (BLEU by hand, human fluency/adequacy, chrF, COMET) and ends with Indic-language MT (low resource, many scripts, rich morphology, IndicTrans2, Bhashini). The end-sem papers give one full question to it every time: an IBM Model 1 E-step/M-step by hand, a BLEU-2 with brevity penalty by hand and a short "what kind of error / why" deployment scenario.

## Must-know facts
- MT goal: preserve meaning, tone and fluency. The core trade-off is adequacy (faithful meaning) vs fluency (natural output); Tbest = argmax faithfulness(T, S) × fluency(T).
- Why MT is hard: ambiguity ("plays the guitar" -> toca, "plays soccer" -> juega), word-order divergence (English SVO with prepositions, Hindi SOV with postpositions, Arabic VSO), rich/agglutinative morphology (Finnish, Turkish, Dravidian), pro-drop (subject omitted and must be inferred), lexical gaps (rivière/fleuve, Schadenfreude), pronoun gender (it -> er because Film is masculine), discourse ("since" temporal or causal), idioms ("break a leg"), named entities and numbers.
- History: RBMT 1950s-80s (SYSTRAN 1968), SMT 1990s-2010s (Google Translate 2006 phrase-based), seq2seq + attention 2014-2017, Transformer 2017+ (GNMT replaced SMT at Google in 2016), LLM-based MT 2020+.
- Vauquois triangle: the higher you analyse the source (words -> syntax -> semantics -> interlingua), the less transfer is needed. Direct translation at the bottom, syntactic transfer, semantic transfer, interlingua at the apex (analysis up, generation down).
- Direct transfer steps: morphological analysis (didn't -> DO:PAST not), lexical transfer, lexical reordering (verde bruja -> bruja verde), morphological generation (dar:PAST -> dio).
- Noisy channel: ê = argmax_e P(e | f) = argmax_e P(f | e) P(e). P(f | e) is the translation model (fidelity, learnt from parallel data); P(e) is the language model (fluency, an n-gram LM learnt from monolingual target text). P(f) is constant for the given input and drops out.
- Word alignment is the latent variable of the IBM models, learnt with EM. Model 1: lexical t(f | e), uniform alignment; Model 2: absolute alignment a(i | j, l, m); Model 3: fertility n(φ | e); Model 4: relative distortion; Model 5: non-deficient distortion.
- IBM Model 1 E-step: P(a_j = i | e, f) = t(f_j | e_i) / Σ_i' t(f_j | e_i'). M-step: t(f | e) = c(f, e) / Σ_f c(f, e), counts summed over every sentence pair. With a uniform start and one 2×2 sentence every posterior is 0.5 and nothing moves; co-occurrence across sentences breaks the tie (casa | house rises to 1/2 after one iteration in the course trace).
- Model 1 is order-blind: it scores "big dog -> hund groß" the same as the unswapped order. NULL (index 0) absorbs target words with no consistent source partner.
- Phrase-based SMT: phrase table extracted from word alignments, reordering (distortion) model, LM, combined log-linearly; decoder = beam (stack) search.
- NMT: encoder compresses the source into vectors, decoder generates token by token. The single fixed-length context vector is the bottleneck (performance drops for long sentences); Bahdanau attention computes a weighted sum over all encoder states at every step (soft alignment).
- Transformer: self-attention + multi-head + positional encodings, decoder with masked self-attention and cross-attention, fully parallel training. Training: shuffle, maxi-batches sorted by length, mini-batches (e.g. 1,600 / 80), 5-15 epochs. Inference: beam search; ensembles; R2L reranking of an L2R n-best list.
- Subwords (BPE) solve OOV and rich morphology; back-translation turns monolingual target text into synthetic parallel data (synthetic source, real target); multilingual models share parameters and enable zero-shot directions.
- BLEU (course): count each candidate n-gram, clip by the max count in any single reference, p_n = clipped / total; BLEU = BP × geometric mean of p_1..p_N; BP = 1 if c > r else e^(1 - r/c). Course examples: 5/8 unigram (love clipped at 2), Cand 1 0.408 × 0.846 = 0.345, Cand 2 0.558.
- BLEU correlates with humans when comparing SMT systems but not SMT vs rule-based (SYSTRAN) or vs human translations. chrF = character n-gram F-score, good for morphologically rich languages; TER = edits to reach the reference; METEOR = synonyms and stems; BERTScore/COMET = neural, better correlation.
- Indic MT: 22 scheduled languages, many scripts, SOV, rich morphology, verbs marked for gender (vaha ... rahaa / rahii hai), code-mixing, low resource. Data from mining multilingual websites (Samanantar, BPCC); script unification helps transfer; related languages share vocabulary, suffixes/postpositions and word order. IndicTrans2 (AI4Bharat, 2023): open Transformer, ~1.1B, all 22 languages, leads IN22 and FLORES; powers Bhashini (MeitY, July 2022).

## Common traps (each one must have at least one question)
- "The TM is P(e | f)" -> the noisy channel uses P(f | e) × P(e); the reversed TM lets the LM own fluency.
- Picking the candidate with the best translation-model score alone -> the product with the LM decides.
- Expecting the first EM iteration to separate a single symmetric sentence pair -> with uniform t every posterior is 0.5 and the update leaves it at 0.5.
- Forgetting to collect counts from every sentence containing the word in the M-step -> wrong denominator.
- "IBM Model 1 penalises the swapped adjective" -> it is order-blind; position arrives in Model 2.
- Clipping by the sum of reference counts -> clip by the max count in any single reference.
- BP flipped (e^(1 - c/r)) or applied to longer candidates -> BP = 1 when c > r.
- Arithmetic mean of p1 and p2 -> BLEU uses the geometric mean.
- High BLEU read as "good translation for users" -> BLEU misses meaning flips such as dropped negation.
- Back-translation with the synthetic text on the target side -> the target must be real; the source is synthetic.
- Greedy decoding assumed optimal -> beam search can find a higher-probability sentence.
- Interlingua thought to need n(n-1) modules -> it needs one analyser and one generator per language.
- Pivoting through English assumed free -> errors compound and gender/honorific information can be lost.
- Treating NMT as easy to control -> NMT is hard to constrain with rules; glossaries/terminology constraints are needed.

## Interview angle
1. **"Explain the noisy channel for MT."** Pick e maximising P(f | e) P(e): a translation model trained on bitext scores fidelity, an n-gram LM trained on monolingual target text scores fluency, a decoder searches. P(f) is constant.
2. **"How does EM learn word alignments without labelled alignments?"** Start uniform, compute expected alignment posteriors per target word (E), turn them into fractional counts and renormalise t(f | e) (M), repeat. Words that co-occur across many sentences pull probability to each other.
3. **"Why did attention matter for MT?"** The fixed-length vector bottleneck broke long sentences; attention gives each decoder step a weighted look at every source state, which also acts as a soft alignment.
4. **"You have 50k Hindi-Tamil pairs and lots of monolingual Tamil. What do you do?"** Start from a multilingual Indic model (IndicTrans2-style), BPE/SentencePiece vocabulary with script unification, back-translate monolingual Tamil, fine-tune; evaluate with chrF plus human adequacy, not only BLEU.
5. **"BLEU went up but users complain. Why?"** BLEU is n-gram precision against references; it can't see negation flips, hallucinated entities or gender errors. Add human adequacy checks, COMET and targeted test suites.
