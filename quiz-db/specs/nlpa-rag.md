## Must-know facts
- RAG retrieves external knowledge at inference time to ground answers in verifiable, up-to-date information without retraining. It targets hallucination, knowledge cutoff, missing citations and domain blind spots. Course analogy: an open-book exam.
- Vector RAG stages: Ingestion (chunk, embed) -> Indexing (vector DB) -> Retrieval (embed query, similarity search) -> Augmentation (query + chunks in one prompt) -> Generation.
- Naive RAG pipeline (slide): Load & Parse -> Chunk -> Embed -> Index -> Retrieve K (cosine / BM25) -> Generate. Chunking: fixed-size (N tokens with overlap), recursive (para -> sentence -> word), semantic (cluster similar embeddings), proposition (atomic facts). Retrieval: dense bi-encoder, sparse BM25/TF-IDF, hybrid + RRF, MMR (diversity), cross-encoder rerank.
- Limits of naive RAG (slide): single-hop only, flat chunk retrieval, no query planning, context-window limits, no entity linking.
- Naive vs Graph RAG (slide): unstructured text vs structured graph; dense vector search vs graph traversal/querying; limited vs enhanced (multi-hop) reasoning; low vs high explainability; moderate vs high integration complexity; general QA vs domain-specific.
- A knowledge graph stores facts as triples (head entity, relation, tail entity); nodes are entities, labelled edges are relations. KG embeddings map entities and relations to vectors (e.g. TransE: h + r ≈ t).
- Graph RAG flow: link query entities to nodes -> traverse / run a structured query (Cypher on neo4j) -> collect the subgraph or paths -> verbalise as context -> generate. Microsoft-style GraphRAG adds community detection (Leiden) and LLM-written community summaries: global questions ("main themes") use community summaries (map-reduce); local questions about one entity use the entity's neighbourhood.
- Agentic RAG: the LLM acts as an agent that sets subgoals, plans retrieval steps, uses tools (search, APIs, calculators) and iteratively refines answers. Components: LLM agent, memory/scratchpad, retrievers/tools, planner/executor. Workflow: query -> plan -> retrieve -> reason -> iterate -> answer.
- Confidence routing (past paper): confidence = sum of top-K similarity scores / K; at or above the threshold answer with naive RAG, below it invoke agentic RAG for more retrieval and verification.
- Course strategy table: basic RAG if data is small and questions simple; hybrid + reranker if accuracy matters; multi-step agentic RAG if questions need reasoning over several documents; structured RAG if data is tables or APIs; Graph RAG if relationships matter.
- RAG variants (slide): Naive (retrieve + generate), Advanced (re-ranking, HyDE, query expansion), Modular (routing, fusion, iterative). Multimodal RAG uses shared embedding spaces (CLIP) across text, images, tables, audio.
- EKG case study: sources wiki, Jira, HR DB, code repos, DMS; entities Employee, Project, Team, Document, Skill, Client, CodeModule; relations WORKS_ON, MEMBER_OF, AUTHORED, RELATED_TO, HAS_SKILL, SERVES_CLIENT, IMPLEMENTS; NER + RE for unstructured text, direct mapping for structured data; agent tools query_EKG (NL -> Cypher) and document_search.
- AskHR: RAG chosen because a base LLM knows nothing about company policy (hallucinates) and extractive QA cannot synthesise complex policies; offline chunk -> embed -> vector DB, online top-3 chunks -> LLM -> cited answer.
- RAGAS: faithfulness = supported answer claims / total answer claims; answer relevance = mean cosine of questions generated from the answer vs the original query; context precision = relevant chunks / retrieved chunks; context recall = GT claims supported by context / total GT claims; hallucination rate = unsupported claims / total claims = 1 - faithfulness.
- Evaluation pipeline (slide): golden dataset (50-500 curated Q&A), automated LLM-as-judge, A/B retrieval tests (chunk size, K, reranker, embedding model), continuous monitoring (drift, latency SLAs, hallucination alerts), human review loop (sample 5% weekly).

## Common traps (each one must have at least one question)
- "Graph RAG replaces vector search for every question" -> it shines on relationship / multi-hop questions; plain lookups from guideline text are naive RAG's job.
- "Agentic RAG is always better" -> higher cost and latency; the course's comparison puts agentic AI at High cost; use it when the question needs decomposition or several sources.
- Confidence exactly on the threshold, or averaging over the wrong K -> follow the formula: sum of the top-K scores / K, compare with the threshold.
- "A KG removes hallucination" -> triples extracted by NER/RE or an LLM can themselves be wrong; validate them (validation agent, constraints).
- Entity linking errors compound -> expected correct links = n × accuracy, and the chance that all n link correctly is accuracy^n.
- Confusing local and global Graph RAG queries -> "what are the main themes across all reports" is global (community summaries); "who manages Project X" is local.
- Thinking naive RAG can answer multi-hop questions reliably -> the answer's facts sit in different chunks with no shared keywords; flat top-k retrieval misses the second hop.
- Picking generative QA (no retrieval) for private company policy -> hallucination, no citations, stale.
- Picking extractive QA when the answer needs synthesis across policy sections -> it can only highlight one span.
- Reading high faithfulness as "the answer is correct" -> it is faithful to what was retrieved, not to the truth.
- BLEU low but BERTScore high -> the answer paraphrases correctly; n-gram overlap undercounts.
- Hallucination rate computed as unsupported / supported -> the denominator is all answer claims.

## Interview angle
1. **"Naive RAG vs Graph RAG vs Agentic RAG: when each?"** Naive for direct lookups in unstructured text; Graph when the answer is a relationship or a multi-hop path (drug-disease-treatment, who-worked-on-what); Agentic when the question needs decomposition, several sources, tools or calculations.
2. **"How would you build an enterprise knowledge graph?"** Define entity and relation types; map structured systems (HR DB, Jira) directly; run NER + relation extraction (or LLM extraction) on wikis and documents; resolve duplicates; validate; load into neo4j; expose a query tool that turns NL into Cypher.
3. **"What is GraphRAG's global search?"** Cluster the entity graph into communities, have an LLM summarise each, answer corpus-wide questions by map-reduce over community summaries; local search starts from the linked entity's neighbourhood.
4. **"Your RAG bot scores faithfulness 0.6. What do you change?"** Generator-side: stricter grounding prompt, claim-level verification, citations required, lower temperature; check retrieval too if context precision is low.
