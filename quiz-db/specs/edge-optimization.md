# Model Optimization for the Edge (M6, S11-S12): coverage spec

**Ladder:** Machine Learning on the Edge (AIMLCZG535) › Module 6 Model Optimization Techniques (Sessions 11-12)   ·   **Prerequisites:** edge-hardware (Flash vs SRAM, accelerators), edge-deployment (TFLite / ONNX Runtime / TensorRT runtimes); nlpa-efficient and llmc-inference cover the same techniques for NLP and LLM serving
**Why it matters for AI/ML:** An edge device has kilobytes to a few gigabytes of memory, a power budget in milliwatts to tens of watts and often no float unit worth using. Module 6 is the toolbox that makes a cloud-trained model fit: quantization (PTQ, QAT), pruning and sparsity, knowledge distillation, neural architecture search, lightweight architectures (MobileNet, EfficientNet, ShuffleNet), small language models (DistilBERT, TinyBERT), compilers (TVM, TensorRT INT8, XLA) and the metrics that prove the result (accuracy, latency, throughput, energy, memory footprint). The papers test it with "the file shrank but latency did not" traps and by-hand arithmetic.

## Must-know facts
- The four levers of Module 6: quantization (fewer bits per number), pruning (fewer weights), distillation (a smaller student), efficient architecture / NAS (a cheaper design). Compilers then make whatever model you have run faster on one target.
- FP32 = 4 bytes, FP16 = 2, INT8 = 1 per parameter: FP32 -> INT8 is 4x smaller. INT8 integer math also cuts energy: a 32-bit float multiply costs ~15-20x an 8-bit integer multiply, and a DRAM read costs ~100x an on-chip SRAM read (Horowitz 2014, 45 nm), so smaller weights that stay on-chip save the most energy.
- PTQ quantizes an already-trained model (no retraining; full-integer PTQ needs a small representative / calibration dataset to find activation ranges). QAT inserts fake-quantization ops during training or fine-tuning so the weights adapt to rounding; it recovers accuracy when PTQ loses too much.
- TFLite PTQ modes: dynamic-range (weights INT8, activations float, quantized on the fly; ~4x smaller, CPU speed-up), full-integer (weights and activations INT8, needs a representative dataset; required by Edge TPU and integer-only MCUs), float16 (2x smaller, for GPUs).
- Affine quantization: real = scale × (q − zero_point); scale = (max − min) / (qmax − qmin); zero_point = qmin − round(min / scale). The range is first widened to include 0 so that 0.0 (padding, ReLU zeros) is exact. TFLite's INT8 spec: weights symmetric per-channel (zero_point = 0, range −127..127), activations asymmetric per-tensor.
- Per-channel quantization gives each output channel its own scale; it matters most for depthwise convolutions, whose channels have very different ranges (the classic MobileNetV2 per-tensor PTQ collapse).
- Unstructured magnitude pruning zeros individual weights: the compressed or sparse-stored file shrinks, but a dense CPU kernel still multiplies the zeros, so latency barely moves. Structured pruning (whole filters/channels) makes the dense tensors smaller and cuts latency on ordinary hardware. 2:4 semi-structured sparsity gets a speed-up only on hardware that supports it (NVIDIA Ampere and later Tensor Cores).
- Pruning works best gradually: prune a little, fine-tune, repeat (TF-MOT PolynomialDecay schedule). Sparsity = zero weights / total weights.
- Distillation: the student learns from the teacher's softened outputs softmax(z / T), T > 1 exposes "dark knowledge" (how similar the wrong classes are). Loss = α·CE(hard labels) + (1 − α)·T²·KL(teacher_T ‖ student_T); the T² keeps gradient sizes comparable (Hinton et al. 2015).
- NAS has three parts: search space, search strategy (RL, evolution, gradient/DARTS), performance estimation (training each candidate, or weight sharing / one-shot supernets). Early NAS cost thousands of GPU-days; weight sharing cut it to a few.
- Hardware-aware NAS optimizes measured latency on the target device (latency lookup tables), not FLOPs. MnasNet's reward is ACC × (LAT / T)^w with w ≈ −0.07; MobileNetV3 and EfficientNet-B0 came from such searches. Once-for-All trains one supernet and extracts specialized subnets per device without retraining.
- Standard conv cost: K²·M·N·H·W multiply-adds; depthwise separable: K²·M·H·W + M·N·H·W; ratio = 1/N + 1/K², so a 3×3 layer is ~8-9x cheaper. Width multiplier α scales cost by ~α², resolution multiplier by ~ρ².
- MobileNetV1 (4.2M params, ~569M MACs) introduced depthwise-separable blocks; V2 (3.4M, ~300M MACs) added inverted residuals with linear bottlenecks (expand ×6, depthwise, project with no ReLU); V3 was found by hardware-aware NAS + NetAdapt and adds h-swish and squeeze-and-excitation.
- EfficientNet compound scaling: depth α^φ, width β^φ, resolution γ^φ with α·β²·γ² ≈ 2 (α = 1.2, β = 1.1, γ = 1.15), so FLOPs grow ~2^φ. B0 (5.3M params, 0.39B FLOPs) came from NAS. EfficientNet-Lite removes squeeze-and-excitation and swaps swish for ReLU6 to be quantization- and accelerator-friendly.
- ShuffleNet uses pointwise group convolutions (cost ÷ g) plus a channel shuffle so information flows between groups. ShuffleNet V2 shows FLOPs are not speed: memory access cost, fragmentation and element-wise ops matter, and equal input/output channel widths are fastest.
- DistilBERT: 6 layers, ~66M parameters, 40% smaller, 60% faster, ~97% of BERT-base's GLUE score. TinyBERT-4: 4 layers, ~14.5M parameters, ~7.5x smaller and ~9.4x faster than BERT-base, ~96.8% of its score, distilled layer-wise in two stages. INT8 on top: DistilBERT ~66 MB instead of ~264 MB, but only if the embedding table (30,522 × 768 = 23.4M parameters) is quantized too; dynamic INT8 of the Linear layers alone leaves ~136 MB. In TinyBERT-4 the embedding table is ~2/3 of all parameters.
- Compilers: TVM (open-source, compiles from many frameworks to many targets incl. microTVM for MCUs, auto-tunes kernels with AutoTVM/Ansor/MetaSchedule); TensorRT (NVIDIA GPUs/Jetson: layer and tensor fusion, kernel auto-tuning, FP16/INT8 with calibration; engines are specific to GPU, TensorRT version); XLA (TensorFlow/JAX: fuses ops in the HLO graph, jit_compile=True).
- TensorRT INT8 calibration runs a representative calibration set (typically hundreds of images) through the network to choose each activation's range; the entropy calibrator minimizes KL divergence between FP32 and INT8 distributions, min-max uses the full range. A calibration set that does not match deployment data gives bad ranges.
- Optimization metrics: accuracy (or accuracy drop), latency (per inference), throughput (inferences/s), energy per inference (power × latency), memory footprint (Flash/storage for weights + RAM for activations and the runtime). Weight compression does not shrink peak activation memory.

## Common traps (each one must have at least one question)
- "80% unstructured pruning should cut CPU latency by ~80%" -> the file shrinks; dense kernels still run every multiply. Use structured (channel) pruning, or hardware with sparse support.
- "PTQ never needs data" -> dynamic-range PTQ needs none, but full-integer PTQ needs a representative dataset for activation ranges.
- "QAT trains the model in INT8" -> QAT trains in float with simulated (fake) quantization; real INT8 comes at conversion.
- Zero point computed without widening the range to include 0 -> 0.0 is not exactly representable; zero padding and ReLU outputs get errors.
- Per-tensor quantization on depthwise layers -> one wide-range channel ruins the scale for all others; use per-channel.
- "Fewer FLOPs = faster" -> depthwise and grouped convs are memory-bound; ShuffleNet V2 and hardware-aware NAS measure real latency.
- Depthwise-separable savings computed as 1/K² only -> the ratio is 1/N + 1/K².
- Width multiplier α = 0.5 assumed to halve compute -> compute scales by α², about 1/4.
- EfficientNet scaled in one dimension only -> compound scaling balances depth, width and resolution; α·β²·γ² ≈ 2 per φ step.
- Distillation with T = 1 -> softmax is nearly one-hot; the dark knowledge is lost. Forgetting T² makes the soft term's gradients ~1/T² too small.
- "Quantization shrinks peak RAM by 4x" -> only if activations are also INT8 (full integer); weight-only/dynamic-range keeps float activations.
- One compiled artefact (a TVM build or tuning log, an XLA program for one input shape) assumed to carry over to another target or shape -> compilers specialise to the target and shapes; build per target and keep shapes static.
- Calibrating INT8 on a few unrepresentative images (e.g. daytime only for a night camera) -> clipped ranges and an accuracy drop in the field.
- "Dynamic INT8 makes DistilBERT 66 MB" -> embeddings stay FP32 unless quantized separately: ~136 MB.
- "60% faster" read as "60% less time" -> it means 1.6x the speed (time ÷ 1.6).
- Optimizing inference on a device whose energy goes to the radio -> Amdahl's law: small battery gain.
- Reporting only model file size -> the edge budget is also latency, energy and peak RAM.

## Interview angle
1. **"Your INT8 MobileNet is 3.5 MB, you pruned it 80% and it is still 45 ms on a Raspberry Pi. Why?"** Unstructured zeros do not skip work in dense ARM kernels; only storage shrank. Prune whole channels (structured) and re-export, or use a runtime/hardware with sparse kernels.
2. **"PTQ or QAT?"** Start with PTQ (minutes, no training pipeline needed); if accuracy drops more than the budget (often depthwise-heavy or small models), fine-tune with QAT for a few epochs.
3. **"Why is a depthwise-separable conv cheaper, by how much?"** Split spatial filtering (K²·M·H·W) from channel mixing (M·N·H·W); ratio 1/N + 1/K², about 8-9x for 3×3.
4. **"How does distillation work?"** Train the student on the teacher's soft probabilities at temperature T plus hard labels, weighted by α, scaling the soft loss by T².
5. **"What does a compiler like TensorRT or TVM add on top of quantization?"** Graph-level fusion and constant folding, per-target kernel tuning and calibrated INT8 kernels; the result is tied to the target device.
