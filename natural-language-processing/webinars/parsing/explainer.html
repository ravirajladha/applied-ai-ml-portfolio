Parsing — teaching a computer to diagram a sentence

A friendly, click-around first look. No maths needed to start — just read, hover, and press the buttons.

★The one idea to hold onto

A sentence looks flat — just words in a row. But hidden inside is a structure: little groups of words that belong together, stacked into bigger groups, up to the whole sentence. Parsing = discovering that hidden structure.

Analogy — LEGO instructions. Words are LEGO bricks. A grammar is the instruction booklet that says which bricks click together into small pieces, and which small pieces click into bigger pieces, until you've built the whole model (the sentence). Parsing is figuring out the build steps just by looking at the finished model.

Why bother? Because meaning hides in structure. "I do not like Frozen" vs "I like Frozen" — nearly the same words, opposite meaning. Where the not attaches is a structure question. Same for translation, question-answering, and grammar checking.

1The building blocks: words → phrases

Words get sorted into categories (their "job"), then categories group into phrases. These are the coloured labels you'll see everywhere:

Word categories (a word's job)

Det a determiner — the a  ·  N a noun — flight meal  ·  V a verb — includes

Phrases (groups that act as one unit)

NP noun phrase = "a thing" (the flight)  ·  VP verb phrase = "an action" (includes a meal)  ·  PP prepositional phrase (with ears)

Rule of thumb: a phrase is named after its most important word (its head). A noun phrase is built around a noun; a verb phrase around a verb.

Test for "is this a real group?" A true phrase moves around as a chunk. John talked [to the kids] [about drugs] ✔  =  John talked [about drugs] [to the kids] ✔ — the brackets slide together, so each is a real unit.

2The grammar = a set of "clicks together" rules

A Context-Free Grammar (CFG) is just a list of rules. Each rule says "this thing on the left can be built from these things on the right." The arrow → means "is made of".

S → NP VP
NP → Det N
VP → V NP
Det → the | a    N → flight | meal    V → includes
👆 Hover or tap any rule above to read it in plain English.

Two flavours of rule: grammar rules (category → categories, like S → NP VP) and lexical rules (category → a real word, like N → flight).

3Apply the rules → you get a tree

Start at S and keep replacing each symbol using the rules until only real words are left. Draw it and you get a parse tree — a family tree for the sentence "the flight includes a meal":

S ├─ NP (the flight) │ ├─ Det ── "the" │ └─ N ──── "flight" └─ VP (includes a meal) ├─ V ───── "includes" └─ NP (a meal) ├─ Det ── "a" └─ N ──── "meal"

Read it top-down as "is made of": the sentence is made of a noun phrase + a verb phrase; the noun phrase is made of "the" + "flight"; and so on down to the words.

4The headache: one sentence, many trees

"I saw the man with the telescope." — Who has the telescope? Both readings are grammatically legal. That's ambiguity, and it's why parsing is hard.

The fix (coming in step 6): give every rule a probability, so the computer can say "reading A is more likely than reading B" and pick the winner. That's a PCFG.

5How the computer finds the tree: the CKY chart

The computer doesn't guess the whole tree at once. It works bottom-up: start from single words, glue neighbours into small phrases, glue those into bigger phrases, until it reaches S covering everything. It records every piece in a chart (a table) so it never redoes work.

Analogy — a knockout tournament. Bottom row = individual players (words). Winners pair up into small teams (phrases), those into bigger teams, until one champion (S) spans the whole sentence. Each cell of the chart = "what can this stretch of words become?"

Press Next step to watch it fill in for "the flight includes a meal". Each cell [i–j] means "the words from position i to j."

Press ▶ Next step to begin. Watch the phrases grow from the words upward.

6Adding probabilities (PCFG) — picking the best tree

A PCFG tags every rule with a probability (how often it's used). The probability of a whole tree is just every rule's probability multiplied together. The tree with the biggest number wins — that's how the computer resolves ambiguity.

For our sentence, the same CKY chart now carries probabilities. Press through to see the numbers multiply up to the final answer:

That final 2.304e-08 is exactly what the notebook's Probabilistic-CKY cell prints. Tiny number — that's normal, since we multiply many values below 1. We only care which tree's number is biggest, not the size.

760-second recap

Grammar (CFG)

Rules saying what's "made of" what. S → NP VP.

Parse tree

The family tree you get by applying rules down to words.

Bottom-up / CKY

Build phrases from words upward, storing each in a chart.

Ambiguity

One sentence can have many legal trees.

PCFG

Rules get probabilities; tree probability = product of rules.

Best parse

The tree with the highest probability wins.

🐍How to not drown in the Python

The notebook looks like a wall of code, but you do not memorise it or write it from scratch. Here's the exact way to make it feel small:

  1. Run first, understand second. Open the notebook, press Shift+Enter on each cell top to bottom. Just watching the output appear teaches you half of it. Nothing breaks — you can always re-run.
  2. Read the story, not every character. Each code cell has a markdown cell above it explaining the idea in English. Read that, look at the output, and only then glance at the code to connect the two. The output is the point; the code is how it got there.
  3. Learn 5 building blocks — that's 90% of this notebook:

    list — a row of things

    xs = ["a","b"] · xs[0] is "a" · len(xs) is 2

    dict — a lookup table

    d = {"the":"Det"} · d["the"] gives "Det"

    for — do it for each

    for w in words: repeats the block once per word

    if — a fork in the road

    if x in cell: runs the block only when true

    def — a named recipe

    def f(x): ... — call it later with f(5)

    print() — show me

    Your best friend. Sprinkle it anywhere to see what a variable holds.
  4. Poke it. Change one number or one word (e.g. swap the sentence to "the meal includes a flight") and re-run. Watching what changes is how it clicks. You can't break anything permanent.
  5. Confused by a line? Copy it into a new empty cell by itself, wrap it in print(...), and run it. Seeing the value of that one piece removes the mystery.
  6. Don't rush. One section per sitting is a win. This notebook is a reference you revisit, not an exam. You've got the matching notebook and README right next to this file.
Mindset: you're learning to read code fluently long before you write it — exactly like understanding a language before you can speak it. Reading + running + tweaking, in small doses, is the whole game.
