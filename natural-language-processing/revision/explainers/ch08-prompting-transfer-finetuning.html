1 · Traditional ML vs LLM development

Analogy. Traditional ML is building a car from parts — you source the components, assemble it, tune the engine. LLM development is hiring a taxi and telling the driver where to go. The car already exists and is better than anything you'd build. Your whole job becomes giving good directions.
Traditional MLLLM development
ExpertiseNeed ML knowledgeUse a pre-trained model / API
DataCollect training dataNo large dataset needed
ModelChoose and train a modelNo training from scratch
ResourcesMore time + GPU / hardwareFar less
The workMinimize a loss functionFocus on prompt writing

The one-line summary: LLMs move the effort from training a model to writing an instruction.

Why transfer learning exists at all — the numbers. Deep learning methods are data-hungry: >50K data items needed for training. The distributions of source and target data must be the same. And labelled data in the target domain may be limited. This problem is typically addressed with transfer learning.

2 · What a prompt is

PROMPT ----> [ model ] ----> COMPLETION prompt = what you send in completion = what the model generates back

Definition to quote: a prompt refers to the input or query provided to the AI model to generate a response. It can be a sentence, a question, or a combination of multiple sentences. The prompt sets the context and guides the model in understanding the desired task or the information it needs to generate its response.

Prompt engineering is the practice of designing and refining prompts so the model produces the output you want — choosing the wording, the format, the context supplied, and the examples included.

3 · ⭐ Zero-shot vs few-shot — build one

Analogy. Asking a new colleague to "summarise these tickets" and hoping they guess your house style — that's zero-shot. Showing them three summaries you already like, then asking — that's few-shot. Neither one retrains the colleague. They just read the examples in front of them, do the job, and forget. That's why it's called IN-CONTEXT learning.
task examples

The key point. In neither case are any model weights updated. Nothing is trained; the examples simply sit in the context window. That is the crucial contrast with fine-tuning in §4 — and exactly the distinction the POS-tagging slides in Chapter 7 were drawing.

THE trap of this chapter. Transfer learning and fine-tuning are constantly confused. There is exactly one distinguishing question:
ARE THE PRE-TRAINED WEIGHTS ALLOWED TO CHANGE? FROZEN -> transfer learning UPDATED -> fine-tuning nothing trained at all -> in-context learning / prompting

Definitions to quote

Transfer learning Using a pre-trained model as a starting point for a new task or domain. Leverage the knowledge acquired on a large dataset and apply it to a related task with a smaller dataset, saving time and computational resources. It involves freezing the pre-trained model's weights and only training the new layers.
Slide's example: in image classification, knowledge gained while learning to recognise cars could be applied when trying to recognise trucks.
Fine-tuning Takes it a step further by allowing the pre-trained layers to be updated. Beneficial when the new dataset is large enough and similar to the original dataset the model was pre-trained on.

Applications of transfer learning

Image classification · Named entity recognition · Sentiment analysis · Cross-lingual learning · Gaming · Image recognition · Speech recognition.
